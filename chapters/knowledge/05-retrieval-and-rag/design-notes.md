# 05 · 設計取捨與疑難

你已經拿到 D14-A，卻還缺下面的未拆封限制。現在有幾個看似合理的選擇：把文件切細、一次多取，或加更好的搜尋。以下每次只問一種選擇什麼時候會吃虧。

主案例仍是 T-1042 r3：12 天、包裝未知，只讀與草稿。D14 已取代 D07，要求天數與未拆封同時符合。

## 取捨一：完整短文件，還是切成小段？

你可能會把每一百字切成一段，好讓搜尋更精準。碰到 A 最後一行、B 開頭寫「上述申請限……」時，代價就出現了：搜尋抓得很準，條件卻被拆散。

對這份短 D14，先讀完整 §2 是便宜的選擇。多讀少量文字，就保住天數與未拆封的關係。文件越長，這個做法才可能帶來無關內容與載入成本。

若長手冊大多只問其中一節，可以用小段找位置，再讀父段理解。代價是保存父段、版本與相鄰關係，並增加一次可能的回讀。

何時換？先測「12 天、包裝未知」與獨立變體「12 天、已拆封」。若切小後常只讀到天數，就改按完整條款切或補父段；若完整載入讓大量舊條款干擾，再縮小範圍。每次看 A、B 是否進候選、進輸入，以及答案是否越界，不只比文筆。

## 取捨二：關鍵字基線，還是加入語意搜尋？

你可能會覺得「買了快兩週」找不到「14 天」，所以直接換成語意搜尋。先確定 D14 真的在資料裡，客服有權讀，而且問題不是索引未更新；否則新搜尋只是在錯資料上更努力找。

只有少量政策時，關鍵字搭配版本範圍容易解釋，也容易查錯。它的弱點是改述漏檢。若標記題持續出現這個弱點，再比較語意或混合方案，才有清楚的升級理由。

代價是索引更新、額外運算與排序診斷。精確商品碼更不能被相近意思沖掉：SKU-1042 不是 SKU-1043。

用同一資料、查詢、身分與取回預算比較，精確題和改述題分開報。若只改述變好、字號題變差，可以分流，不必逼所有查詢走同一條路。沒有實測資料時，不宣稱哪種已經勝出。

## 取捨三：增加取回數，還是補讀父段？

你可能會把取回數從 2 改成 20，希望 B 自然出現。它可能有效，也可能只是把更多 D07 和無關內容放進來。

如果已命中 A、知道同節未完，補讀 §2 有明確目的；如果連 D14 都沒找到，就該先查資料、查詢與候選範圍。這時重排也無法補出缺席的 D14。

只有候選已含必要段落、但相關排序混亂，才比較重排的增益與額外成本。分別記「補找後 B 出現了嗎」和「選段後 B 留下了嗎」，不要只用最後一個總分掩蓋過程。

## 疑難表：同樣答錯，修法不同

需要快速回來定位時，看這張小表即可；不用重讀三項取捨。

| 觀察 | 優先查的位置 |
| --- | --- |
| 候選沒有 B | 切段、查詢、條款回讀 |
| 候選有 B，輸入沒有 | 選段與 context 組裝 |
| 輸入有 B，仍說一定可退 | 生成與逐句支持驗收 |
| 答案沒 X99，輸入卻已有 | 授權與原文取得路徑 |
| 新政策已上線，仍讀舊段 | 索引、快取與版本失效 |

判斷依可見資料與事件，不要求模型公開隱藏思考鏈。先用 [Q03](exercises/README.md#c05-q03) 練定位，再用 Q04 把修正寫成可檢查的契約。
