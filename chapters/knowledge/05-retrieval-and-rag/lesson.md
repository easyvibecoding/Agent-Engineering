# 05 · Retrieval 與 RAG

[章節入口](README.md) · [設計取捨](design-notes.md) · [練習](exercises/README.md)

## 本章完整案例

員工詢問最新版退款規則，系統檢索到含「退款」最多的舊文件，以及另一部門無權公開的附件。模型引用真實段落，但結論不適用。

案例與練習軌跡為合成教學資料，沒有執行真實業務操作。

## RAG 的基本分工

檢索負責找可能有用的外部資料，生成負責在資料與任務條件下回答。RAG 不等於某一種向量資料庫，也不保證避免幻覺。要分別驗證是否取回需要的證據，以及答案是否忠實使用證據；兩者的改進方向不同。

## 從文件到可引用片段

切分時保留標題、章節、文件 ID、版本、生效時間與原文位置。太小的片段可能丟失例外條件；太大的片段增加噪音。相鄰段落回讀或結構感知切分可保留上下文，實際大小應依問題與文件格式評估，沒有通用最佳 token 數。

## 檢索與重新排序

關鍵字搜尋擅長精確代碼與專有名詞，embedding 檢索可找語意近似內容。Hybrid retrieval 結合兩者，但原始分數可能不可直接相加。Reranking 在候選集上重新判斷相關性，會增加延遲；候選集根本沒有正確文件時，reranking 不能憑空補回它。

## 權限與新鮮度

先在可授權範圍內取回資料，不能等模型看完機密後再用 prompt 要求保密。版本與生效日期也需明確政策，檢索分數不能替你決定哪個版本有效。更新或刪除來源後，索引與快取需要同步失效或標記，避免舊內容持續被引用。

## Agentic retrieval 與評估

固定檢索一次較容易預估；Agent 可根據缺口改查詢、讀鄰近段落或查原文，但需搜尋預算與停止條件。以人工標記需要的證據衡量檢索召回，再檢查答案的引用支持與拒答品質。訂閱 Responses preview 未提供 hosted file search；未來可在本機實作搜尋工具，不能假設平台代管檢索可直接沿用。

## 用案例走一次

先依使用者權限縮小文件範圍，再選適用版本；取回退款主條款與相鄰例外段落。若新舊文件衝突且無生效依據，回答保留未知並指出所需來源。把「取回了哪份文件」和「用它支持了哪項結論」分別記錄。

## 三個帶走的問題

- 能把檢索失敗與答案生成失敗拆開：你會怎麼向另一位工程師說明？
- 能設計有版本、引用與權限邊界的檢索流程：需要哪些證據才能判斷？
- 如果模型的建議錯誤，哪一層應阻止錯誤擴大？
