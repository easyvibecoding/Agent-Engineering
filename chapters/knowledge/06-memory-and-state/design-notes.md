# 06 · 疑難與設計理由

[正文](lesson.md) · [題目](exercises/README.md)

## 需要說得出理由的選擇

### 1. 保存完整歷史還是狀態摘要？

設計理由：完整歷史便於稽核，但噪音、儲存與隱私成本較高。

替代方案與改選條件：摘要便於恢復，關鍵事件仍保留可回查位置與精確 ID。

### 2. 跨任務共享還是任務隔離？

設計理由：共享可降低重複查找，但要有授權、來源與失效規則。

替代方案與改選條件：任務事實預設留在任務範圍；只有經確認的共用知識才提升作用域。

## 常見疑難

### 疑難 1：有記憶檔就代表模型會自動記得

需設計取回、選取與載入。

### 疑難 2：重啟後照 checkpoint 重做即可

先查外部狀態，checkpoint 與副作用未必原子完成。

## 如何證明選擇有用

以本章案例固定資料與成功條件，只改一項設計；記錄結果、失敗與必要資源。替代方案不是一律較差：回答何時改選，以及你會觀察什麼。尚未執行的驗證清楚標為待驗證。
