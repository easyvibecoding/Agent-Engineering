# C06 · 面試與追問

## 主問題與短答骨架

用兩分鐘解釋 context、memory/store、checkpoint，再說明「有記憶為什麼仍會錯」。先自答，以下骨架僅協助組織，不是逐字稿。

1. 需求：重啟後接續 T-1042，但工單可能更新。
2. 責任：context 是當輪實際輸入；store 保存可再取資料；checkpoint 記錄某任務停在哪。
3. 例子：r3 拆封未知，今天可信 r4 已拆封；保留歷史並更新目前判斷，依 D14 更正草稿。
4. 限制：保存不保證自動載入、永遠有效或具備讀取權限；RAM 也不保證跨程序保留。
5. 驗收：用版本未變、版本更新、讀取失敗、別案四個恢復案例檢查不同輸出。

## 追問順序

| 追問 | 面試官想確認什麼 |
| --- | --- |
| 既有全部聊天，何必另寫交接？ | 了解訊息歷史與目前狀態不同，且摘要可能丟條件 |
| 哪些要重查？ | 能挑出會改變下一步的事實，不一律全重跑 |
| r4 比 r3 新就一定可信嗎？ | 會檢查同案、來源與適用性，而非只比數字 |
| 草稿交付後重啟，需要重寄嗎？ | 不混淆產物與副作用，也不假設有寄送授權 |
| 使用者 B 查同關鍵字呢？ | 先限制可查身份範圍，不靠模型口頭保密 |
| 要刪掉一項偏好，怎麼驗收？ | 能考慮摘要、索引及預設載入，不只刪一列 |

## 常見弱答怎麼補

- 「用向量庫讓它記住」：補出保存對象、身份範圍、來源、載入時機與有效期；向量檢索不替你確認現況。
- 「重啟全部重跑最安全」：指出可能重做外部操作；先查哪些已完成、哪些未知，再決定可重做步驟。
- 「checkpoint 保證恢復正確」：改成它保存當時狀態；r4 仍需來源核對，外部效果也不一定與本機同步。
