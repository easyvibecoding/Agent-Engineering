# C06 · 參考解答

[回題目](README.md)

請先自答再閱讀。以下是可辯護的參考方案；只要假設、權限、取捨與驗證一致，也可接受其他設計。

<a id="c06-q01"></a>

## C06-Q01

context 為當輪；待辦與操作狀態屬任務；經使用者確認的偏好可跨任務；來源事實帶版本與可回查位置。每類都要能更正或失效，避免任務間互相覆蓋。

**自評：**交付四類資訊的範圍與失效方式。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c06-q02"></a>

## C06-Q02

可保存經遮蔽的必要事件供稽核，當輪只載入高相關摘要與引用。高風險操作保留精確結果位置；不必讓模型每次重讀全部歷史。依恢復品質與資料成本調整。

**自評：**交付保存／載入的兩層策略。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c06-q03"></a>

## C06-Q03

先按 operation ID 或目標版本確認同一操作確已完成，補記已確認結果後繼續後續驗收。無法對應時保留未知，不把另一筆完成結果誤認成自己的操作。

**自評：**交付查證、補記與歧義分支。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c06-q04"></a>

## C06-Q04

保存內容、來源、適用使用者／任務、確認時間與失效條件；刪除或更正時同步相關索引與摘要。可用簡單檔案或表格，先確保範圍與生命週期明確。

**自評：**交付資訊欄位、授權與失效傳遞。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c06-q05"></a>

## C06-Q05

context 是當輪可見資訊；memory 是可保存再取用的資訊；checkpoint 記錄恢復工作需要的狀態。恢復仍需對外部系統讀回，不能把保存快照當成外部結果。

**自評：**交付三項區分與恢復例子。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c06-q06"></a>

## C06-Q06

以本機任務紀錄與資料檔為目標，在推論前、工具執行後、狀態保存前中斷；恢復後核對狀態，不重複套用已完成修改。測試記憶過期與跨使用者隔離。

**自評：**交付中斷點、恢復策略與驗收案例。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
