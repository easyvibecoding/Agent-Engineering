# C08 · 分級提示

先保留自己的答案。第一級提示定位問題，第二級才縮小範圍；請先嘗試修正，不必一口氣往下讀。

<a id="c08-q01"></a>

## C08-Q01

**第一級：**先把「是誰」與「允許用什麼」畫成兩個欄位。再想工單工具由哪個系統授權。

**第二級：**查 token response 實際 granted scopes；不要從申請時的 scopes、ID token 或別的 client 登入推導本 app 的方案使用權。

[回題目](README.md#c08-q01)

<a id="c08-q02"></a>

## C08-Q02

**第一級：**不要用「哪個比較新」選方案。先問 A 是否要親自排每一步，B 是否主要做介面與整合。

**第二級：**將工具循環、OAuth 刷新、任務驗收分欄；用了現成 harness，後兩欄仍需要負責者。

[回題目](README.md#c08-q02)

<a id="c08-q03"></a>

## C08-Q03

**第一級：**先找這輪真正的終止事件，再分開看早先已完成的工具紀錄。

**第二級：**HTTP 200 不能覆蓋 failed；缺重設資訊就保留未知。請保留已知 r3，但將「可以…」標未完成，不把它拼成資格結論。

[回題目](README.md#c08-q03)

<a id="c08-q04"></a>

## C08-Q04

**第一級：**把兩個 call_id 寫在紙上，工具先回政策結果時該放哪一格？

**第二級：**下一輪既要知道「問了什麼」，也要知道「哪個結果回答哪個要求」。被拒絕可以回傳拒絕原因；失敗推論的候選則未取得本課的執行資格。

[回題目](README.md#c08-q04)

<a id="c08-q05"></a>

## C08-Q05

**第一級：**先說誰管登入，再說誰管 loop，最後說誰驗收業務內容。

**第二級：**找一個 response.completed 只有工具要求的時點，用它反駁「推論完成=客服完成」。再補 12 天與 unknown 的草稿驗收。

[回題目](README.md#c08-q05)

<a id="c08-q06"></a>

## C08-Q06

**第一級：**同樣顯示不可用，缺 scope、暫時 unavailable、refresh 確認失效需要不同下一步。

**第二級：**token 更新列要指出已啟動子程序不會自動取得新環境值；每列加一個具體觀測欄，所有測試狀態先填未執行。
