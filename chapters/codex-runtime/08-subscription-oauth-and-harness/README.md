# 08 · 訂閱 OAuth、Responses 與自建 Harness

章節 ID：C08 · 內容修訂：2026-10-21 · 核心約 2–3 小時 · Lab 僅規格。

## 這章要解決什麼

**如果我想親自決定 Agent 每一步，合格的訂閱授權、模型推論與本機工具要怎麼接？**

上一章用了 Codex 的現成 harness。這章把循環拆開，練習辨認授權、推論、工具、草稿四層狀態；不是拿原生登入檔當自己的 app 憑證。

本章產物：一張授權檢查表、一段三次推論／兩次讀工具的合成事件表，以及包含停止原因的草稿驗收。

## 具體前置與跳章入口

不需前章 lab 或任何登入資訊。先確認能說清楚：

- 模型提出工具要求，與工具真的執行，是兩件事；不清楚可回 [C03](../../agent-core/03-tool-contracts/README.md)。
- 進度要保存來源、未知與權限；不清楚可回 [C06](../../knowledge/06-memory-and-state/README.md)。
- Codex app-server 是客戶端整合入口；不清楚可看 [C07](../07-codex-runtime/README.md)。

共同合成案例：T-1042 r3，10/08 至 10/20 相差 12 天。D14 要求 ≤14 天且未拆封，r3 拆封未知。任務只有讀取及草稿。正文會重述資料，跳章不需先跑環境。[完整共同案例](../../../maps/course-story.md)

## 怎樣算懂了

給你「200 → 文字片段 → failed」，你不會把片段當成答案。給你兩個反序返回的工具結果，你能按 call_id 配對。給你 completed 加讀工單要求，你能指出還缺工具執行與草稿驗收。最後保留 r3 的拆封未知，不把日期符合說成退貨核准。
