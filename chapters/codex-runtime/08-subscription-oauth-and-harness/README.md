# 08 · 訂閱 OAuth、Responses 與自建 Harness

你看到模型寫「請讀工單」，接著畫面顯示 completed。這時該交答案，還是輪到你的程式做事？從這個時刻開始讀，會比先背 OAuth 欄位更容易看懂自己要接手什麼。

## 這章要解決什麼

上一章由 Codex 管循環；這章試著由你控制下一步。先跟著 [正文](lesson.md)走三次推論：讀工單、讀店規、寫草稿。每一段只多做一個判斷。

這是合成故事與抽象教學，約 2–3 小時。只做規格，不需要登入資訊，也不啟動 OAuth、推論或 lab。章節 ID：C08；內容修訂：2026-10-21。

## 具體前置與跳章入口

可以直接開始。正文會重述 T-1042 r3 的背景：12 天符合 D14 天數條件，拆封未知，只准讀取與草稿。[完整共同案例](../../../maps/course-story.md)可在需要時回查。

若你卡在「模型要求」與「真正執行」的差別，回 [C03](../../agent-core/03-tool-contracts/README.md)。卡在恢復時要記什麼，回 [C06](../../knowledge/06-memory-and-state/README.md)；想先用現成循環，再看 [C07](../07-codex-runtime/README.md)。不必先完成任何 lab。

## 核心與深挖怎麼分

先讀正文開場到「先在這裡停，或繼續深挖」，約 35–45 分鐘。停下來試著說：模型第一次 completed 時，為什麼尚未讀到工單？

接著做 [Q01、Q03、Q05](exercises/README.md)，保留第一版。卡住只開該題的[第一級提示](exercises/hints.md)；修正後，需要才看[解答](exercises/solutions.md)。7 天路線可先做 Q01、Q05。

OAuth 七檢查、完整回放資料與 preview 參數都放深挖。你可以先略過長表，等自己問出「該驗哪一項」「歷史怎麼帶回」再打開。閱讀 [設計取捨](design-notes.md)或做 Q02、Q04、Q06 時再細讀，不需第一輪全部背完。

想用對話接讀，就選 [Codex 卡](codex.md)的一張；想口答，開 [面試](interview.md)，一次只追一題。[lab](lab/README.md)保持未來驗收契約，這期不寫程式。

## 怎樣算懂了

你能接著故事往下走：登入不等於獲准推論；推論完成不等於工具已執行；草稿完成也不等於退貨資格確認。工具結果配回原要求，r3 的未知保留到最後。
