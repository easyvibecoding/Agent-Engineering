# 08 · 疑難與設計理由

[正文](lesson.md) · [題目](exercises/README.md)

## 需要說得出理由的選擇

### 1. 自建 loop 還是接 Codex harness？

設計理由：自建 loop 能直接研究行動選擇、停止與狀態語意。

替代方案與改選條件：Codex 提供現成執行系統，但需遵守其 RPC、版本與工具能力；以同任務比較控制需求。

### 2. 認證後立即推論還是先檢查授權？

設計理由：必須確認授權範圍與所選帳號，不能以 ID token 或登入成功代替。

替代方案與改選條件：資格或政策不允許時保留狀態並說明限制，不反覆 OAuth 或自動換計費。

## 常見疑難

### 疑難 1：任意 Codex OAuth token 都可當平台 API key

本路線使用 app 自己的合法註冊與 granted scope，不假設可移用其他 client 的 token。

### 疑難 2：HTTP 200 或第一段文字等於推論成功

必須消費終止事件並區分 completed、failed、incomplete 與斷線。

## 如何證明選擇有用

以本章案例固定資料與成功條件，只改一項設計；記錄結果、失敗與必要資源。替代方案不是一律較差：回答何時改選，以及你會觀察什麼。尚未執行的驗證清楚標為待驗證。
