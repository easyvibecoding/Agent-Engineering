# 08 · 設計取捨與疑難

本章固定任務是讀 T-1042 r3 與 D14，交條件式草稿。日期差 12 天符合 ≤14 天；拆封未知，無寄送、關單或退款授權。下列是工程選擇，不是「官方只有一種正解」。產品限制依[正文來源](lesson.md)於 2026-10-21 的查證範圍。

## 取捨 1：自己控制 loop，還是沿用 Codex harness？

**何時自己做：**學習目標是指出每次推論的輸入、工具要求、結果及停止；或者產品確實需要與既有 harness 不同的控制流程。T-1042 的三次推論很好用：每一輪增加一份必要證據，而非盲目多跑。

**代價：**你要處理不完整串流、call_id 配對、模型 output items 回放、工具拒絕、取消與進度保存。省略其中一項並不代表系統更簡單，只是把錯誤延後到恢復時才出現。

**何時換：**如果主要交付是客服操作台、核准畫面與既有工具整合，可讓 app-server 管 Codex loop。app 仍負責自己的 OAuth 與憑證生命週期，並驗收草稿；不能只因收到 turn/completed 就省掉 turn.status 與內容檢查。

**如何驗證：**拿同一批假事件比較兩張責任表。無論哪條路，都要能回答：誰擋 close_ticket？誰把 unknown 保留到最後？誰在額度中止時保存進度？把責任交出去可以，但不能讓責任消失。

## 取捨 2：工具要求一到就執行，還是等推論終止？

**本課選擇：**等 response.completed、工具參數完整，再驗權與執行。這樣 response.failed 發生在半段 arguments 後時，沒有提前讀資料或產生副作用。

**代價：**可能比提早排程多一些等待時間。本課沒有實測延遲，不能因此宣稱慢多少；也不聲稱提前排程一律不成立。

**何時考慮改：**延遲成為量測到的瓶頸，且只針對完整、可撤銷或可安全重複的動作，有明確取消與結果處置。寫入尤其要另設不可逆效果的界線。不能只把「模型還在輸出」當執行許可。

**如何驗證：**比較 A2 工具要求後，分別收到 completed、failed、斷線三條合成事件。保守版本只有第一條能進入工具驗權。若採提前版本，必須逐條說明已啟動工具如何取消、讀取結果是否暴露，以及使用者介面顯示什麼。

## 取捨 3：完整保存歷史，還是每輪只帶摘要？

HTTP store=false 與不使用 previous_response_id，讓 app 承擔必要歷史的責任。「保留」不等於永遠傳全部資料；「壓縮」也不能刪掉配對所需的模型輸出與工具結果。

| 做法 | 適用 | 代價與換法 |
| --- | --- | --- |
| 保留必要原始 items 與工具結果 | 本章短任務、恢復可回查 | input 會變長；真正有壓力才量測並設壓縮策略 |
| 另加任務摘要 | 長任務快速定位進度 | 摘要可能漏 unknown、版本與權限；保留來源及可恢復的工具配對 |
| 只存一段「工單已讀、可退貨」 | 本例不適用 | 丟掉 r3 的未知與 D14 第二條件，無法驗收，也可能破壞工具歷史 |

驗證方式不是只問摘要讀起來順不順。請恢復到請求 C，檢查能否找到 call_ticket_01、call_policy_02、各自對象與結果；草稿是否仍保留拆封未知。

## 取捨 4：失敗就重新登入，還是按錯誤分類？

重新登入會打斷使用者，也未必能解決參數錯誤或額度限制。分類的代價是需要保留實際 HTTP 狀態、錯誤碼、request ID、發生階段和本機工具紀錄。

- 缺 scope：方案推論未啟用，等使用者主動選擇重新授權。
- usage_limit_exceeded：暫停新請求，看官方 Usage；重登不會證明額度已恢復。
- unsupported_capability：修正不支援的請求項目，原樣重試沒有意義。
- 暫時基礎設施失敗：保留憑證，有限退避；不要把可用註冊清掉。
- 確認 refresh token 已不可用：才走重新授權，並保留正確 issued client_id。

如何驗證：設計兩個相同「不能推論」畫面背後的事件，一個缺 scope、一個 usage_unavailable。若兩者下一步完全一樣，表示分類仍未進入實際控制流程。

## 疑難診斷：把一句模糊話改成可檢查的主張

| 弱說法 | 補成可驗收的句子 |
| --- | --- |
| 「OAuth 成功了」 | 「ID token 已驗證；token response 的 granted scopes 包含方案使用權；此帳號與 client 對應正確」 |
| 「API 回成功了」 | 「這次 Responses 收到 completed，output 是讀工單要求；工單工具尚未執行」 |
| 「結果有存起來」 | 「已保存任務契約、來源版本、推論終止狀態、工具要求及其 call_id 結果；憑證分開保護」 |
| 「更新 token 就好」 | 「app 已刷新並完整保存新憑證；env_key 子程序須重啟、初始化並 resume；舊程序不會自動取得新值」 |
