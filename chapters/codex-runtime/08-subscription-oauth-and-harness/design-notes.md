# 08 · 設計取捨與疑難

你要做本機客服助理，自己決定讀工單、讀店規、何時停。它想經使用者同意使用 ChatGPT 方案額度；這不是把既有 Codex 登入檔搬進程式。

## 取捨 1：自己做 loop，還是接 Codex？

想練每輪工具、歷史與停止，就自己安排；代價是也要處理恢復。

**什麼情況換做法：**重點是做客戶端與工具整合，可讓 Codex 管既有 loop，保留自己的業務驗收。

## 取捨 2：一看到文字就顯示成功嗎？

可顯示進度，但仍等待終止事件與產物驗收。

**什麼情況換做法：**中途失敗時把片段標未完成，不能為了介面順暢而當最終答案。

## 常見卡點：錯在哪裡，怎麼改

| 容易說出口的話 | 問題在哪裡 | 較可靠的做法 |
| --- | --- | --- |
| 有任意 OAuth token 就能呼叫。 | Token 對應註冊與授權，不能直接互換。 | 使用 app 自己的合法流程並檢查 granted scope。 |
| response.completed 就是客服任務完成。 | 可能只完成一個工具要求的推論。 | 接著驗證與執行工具，再判斷整體交付。 |

## 拿本章案例檢查

拆成三層後，登入失敗、模型串流失敗和工具越權不會混成同一種錯。也能用相同客服題目比較自己的 loop 與 Codex 整合，而不偷換成功標準。 用[診斷題 Q03](exercises/README.md#c08-q03)檢查是否能指出具體錯誤，再以 Q04 說明自己的方案。答案若只剩「加強安全／優化流程」，補寫對象、條件與可觀察結果。
