# C08 · 面試與追問

## 主問題與 90 秒骨架

「用訂閱自己做 harness，和直接用 Codex，是不是同一件事？response.completed 為什麼還不等於任務完成？」

第一回先只回答「用誰的循環」，限 30 秒。等對方追問 completed，再用一個工具時點補 30 秒。最後才把兩段連成 90 秒；下面骨架供答完檢查，不必起手全背：

1. **需求：**我要親自排 loop，還是做現成 harness 的客戶端？
2. **責任：**原生 Codex、自己 OAuth＋Responses、自有 app＋app-server 三路，誰管授權、誰管循環？
3. **事件：**read_ticket 的要求完成推論後，本機仍須驗權、執行、按 call_id 回填。
4. **業務驗收：**12 天符合 D14 天數，r3 拆封未知，只能詢問草稿。
5. **證據：**目前只有設計與合成事件，不聲稱已取得授權或已完成 lab。

## 常見弱答怎樣改善

**若你只說「OAuth 就是登入，Responses 就是 API」。**先停在登入畫面：現在知道是誰，還是知道此 app 獲准用方案？補出差別：ID token 經驗證辨認帳號；granted scope 決定自己的 app 能否使用方案；API 呼叫仍可能失敗。最後指出工單權限另管。

**若你說「completed 了就把結果印出來」。**先回到第一個 completed。它帶回的是工單，還是讀取要求？先檢查 output 是否為工具要求。若是，列出驗權、執行、結果配對；若是文字，檢查 D14、r3 與未知。不要靠同一個「完成」字眼跳過責任。

**若你說「限流就切模型／切 API key」。**先問自己錯誤碼實際告訴了什麼。說出精確錯誤與復原條件；usage_limit_exceeded 不提供重設時間，也不等於整個方案用完。換模型不保證避開限制，自動切計費不是本題授權。

## 自評與追問節奏

各 0–2 分：責任是否分清、是否用事件與 call_id、失敗分類是否具體、是否保留未知及證據界線。0 是沒回答，1 是只有術語，2 是能用本例說明。先口答再追一題，修正後重講 30 秒；此分數不是實際面試成果。

需要時再看 [Q05 參考解答](exercises/solutions.md#c08-q05)；設計、實作、實測三種成果要分開說。

**下次口答從這裡接：**我卡在 ___ 追問；下一次先用 ___ 事件回答，不重新背整段。
