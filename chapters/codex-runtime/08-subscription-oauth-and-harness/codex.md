# C08 · Codex 協作卡

目標是讓你自己說出每個決策，而不是讓 Codex 代跑 OAuth。預設只讀正文、設計取捨與題目；未要求提示或解答時，不讀 hints.md／solutions.md。不建 lab、不讀真實憑證、不改全域設定。

## 卡 1：逐關授權教練

「我在學 C08。先只問我：ID token 有效、但缺方案 scope 時，介面應顯示什麼？等我自答再追問：state、nonce、PKCE 各綁哪一段？issued client_id 與 host ID 哪個能當授權證明？每次只追一題。若我只說『驗證安全』，請我說明要比對哪份資料；不要直接給全套答案。」

## 卡 2：事件桌上推演

「請依正文合成案例當事件主持人。一次給我一個事件：工具要求、completed、本機讀取結果、下一輪。每次先等我說現在已知什麼、可做什麼、不可宣稱什麼，再公布下一事件。在其中一輪改成 failed，問我哪個動作要停。不要啟動請求，也不要假裝事件是真實 log。」

## 卡 3：call_id 配對審閱

「我會貼 Q04 的表。先檢查 call_ticket_01 與 call_policy_02 是否對應正確目標、版本及結果；再問必要 input 少了什麼；最後問 r3 的 unknown 是否保留。若有錯，只指出第一個錯配並問我如何修，不立刻重寫完整答案。」

## 卡 4：恢復面試官

「先問 Q03，等我自答後依序追問：HTTP 200 代表什麼？已完成的工單讀取能保留嗎？配額碼告訴了什麼、沒告訴什麼？何時重登？app-server env_key 更新後要對程序做什麼？請把我混用的『成功』換成具體層級，要求我修正後再評分。」

## 卡 5：未來規格審閱

「我只交 Q06 的未來驗收表。依授權、推論、工具、交付順序，逐列找無法客觀驗收的句子，例如『正常恢復』。請問我要看到哪個事件、配對、來源與狀態才算正常；所有執行欄維持未執行。不要建 app、環境或讀憑證。」

## 收尾：讀者保留自己的修正

每次對話留三行：原判斷、錯在哪個層級、修正後要查的證據。可用目前可選的訂閱模型作教練，但回答流暢或模型列在選單，不代表練習已驗收；先依題目資料檢查推理。
