# C07 · 未來 Lab 規格

先想像未來畫面要怎麼回答「到底完成什麼」，再寫驗收，不急著選語言。

狀態：**只有驗收契約，尚未建立程式、安裝環境、登入或執行。**

## 要練的工作

觀察 Codex 事件，正確區分讀取完成、本輪完成、草稿驗收與業務進度。只用假工單，不對真實客服系統操作。教學推論優先採合格訂閱路線，不能遇阻就切換 API key。

## 獨立輸入與預檢

第一步只列輸入：T-1042 r3、D14，12 天、拆封未知、只准草稿。保留來源與版本，不依賴其他 lab 狀態。

第二步才選 exec 或 app-server 一種事件來源。規格留出 CLI／SDK 版本、登入方式、有效權限及可用工具欄；目前都待驗證，不讀取或複製真實憑證。

## 三組驗收案例

| 案例 | 預期事件／觀察 | 預期呈現 | 不可通過的行為 |
| --- | --- | --- | --- |
| 成功草稿 | 正確終止成功；草稿完整 | 本輪完成；日期符合；拆封待確認 | 自動顯示已核准、已寄送或已退款 |
| 讀取後失敗 | 一個讀取 item 成功；整輪失敗 | 失敗及已知進度；片段未交付 | 讀取成功被當全輪成功 |
| 連線中斷 | 未收到可靠終止狀態 | 狀態未知，規劃讀回 | 未查狀態就宣稱失敗／成功或重做寫入 |

若先用合成 trace 檢查畫面，只能記「合成事件檢查」；未來真實 Codex 執行另外留下輸入、來源、版本及結果，不把二者混成一份實測證據。

## 沒有副作用，要看什麼

先問「做得到嗎」：不提供寄送／關單／退款能力。

再問「有完整觀察嗎」：保存相關工具紀錄；若接隔離假服務，讀回狀態及操作紀錄。最終文字「沒有關單」不單獨構成證明；若日誌不完整，結果標為證據不足。中斷也不表示先前動作已回退。

## 環境與清除

這段可等三案規格寫完再補；不必現在啟動環境。

只指定必要假輸入；草稿回傳畫面，可變事件與產物放本 lab/.local/。個人答案放 repo .study/。將來若安排實作，再決定語言、獨立依賴、啟動／停止與清除方式；不在本次建立。資料夾隔離不證明 sandbox，也不隔離帳號共用配額。

未來驗證需列出允許讀取、越界讀取與寫入的實際結果，以及外部工具權限。不要用 cwd 或 read-only 名稱替代有效控制證據。
