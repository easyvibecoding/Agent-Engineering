# 07 · 設計取捨與疑難

你要讓 Codex 讀教學工單 T-1042 與 D14，交條件式草稿。也想知道：直接用 CLI、從程式驅動，或做一個帶核准畫面的客戶端，各該從哪個入口開始。

## 取捨 1：CLI／exec 還是 app-server？

一次性唯讀報告先用較薄入口，減少連線和事件處理。

**什麼情況換做法：**需要自訂核准、歷史與串流畫面時，再承擔 app-server 的客戶端責任。

## 取捨 2：相信列出的模型還是測實際可用性？

清單可用來選候選，不能當帳號授權或成功推論的證據。

**什麼情況換做法：**未來需在相同登入與路線完成一次受限請求，仍不外推成全課跑通。

## 常見卡點：錯在哪裡，怎麼改

| 容易說出口的話 | 問題在哪裡 | 較可靠的做法 |
| --- | --- | --- |
| turn/completed 就是退款完成。 | 把執行輪次和業務動作混為一談。 | 查狀態，再查產物與真正工單。 |
| Codex SDK 和 Agents SDK 是同一回事。 | 控制層與責任不同。 | 先指出誰掌控 loop，再選套件。 |

## 拿本章案例檢查

使用者看得到文字串流時，很容易誤以為整件事已成功。把事件對回任務與產物，才能避免漂亮的進度畫面掩蓋失敗。 用[診斷題 Q03](exercises/README.md#c07-q03)檢查是否能指出具體錯誤，再以 Q04 說明自己的方案。答案若只剩「加強安全／優化流程」，補寫對象、條件與可觀察結果。
