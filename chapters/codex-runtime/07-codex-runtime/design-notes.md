# 07 · 疑難與設計理由

[正文](lesson.md) · [題目](exercises/README.md)

## 需要說得出理由的選擇

### 1. CLI／exec 還是 app-server？

設計理由：單一自動化任務先選較薄的入口，減少事件與連線責任。

替代方案與改選條件：需要互動核准、持續串流與自訂 UI 時再使用 app-server，並查該版本成熟度。

### 2. 使用既有 harness 還是自行建 loop？

設計理由：既有 harness 提供成熟的工具與狀態機制，整合較少。

替代方案與改選條件：研究控制策略或精細語意時自建 loop，代價是自己承擔工具、歷史與恢復。

## 常見疑難

### 疑難 1：model/list 有模型就代表可用

清單與實際 entitlement 分開；完成推論才驗證該次請求可用。

### 疑難 2：turn 結束就表示程式已修好

檢查 turn.status、產物與必要驗收，分開記錄。

## 如何證明選擇有用

以本章案例固定資料與成功條件，只改一項設計；記錄結果、失敗與必要資源。替代方案不是一律較差：回答何時改選，以及你會觀察什麼。尚未執行的驗證清楚標為待驗證。
