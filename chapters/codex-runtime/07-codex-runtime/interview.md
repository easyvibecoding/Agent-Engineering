# C07 · 面試與追問

## 主問題

用客服工作台例子解釋 Codex SDK、app-server、Agents SDK 怎麼選。先口答 90 秒，再對照骨架，不逐字背答案。

## 短答骨架

1. **需求：**只有程式化產出草稿，還是要自訂歷史、事件與核准 UI？
2. **選擇：**Codex SDK 使用現成 Codex；app-server 適合深度客戶端整合；自己應用的 Agent 編排另評估 Agents SDK。
3. **責任：**沿用 harness 仍要提供 r3／D14、限制工具、核對內容及外部結果。
4. **證據：**正確終止狀態加上草稿驗收；拆封未知使業務仍待確認，不能說已退款。

這是口答結構，不是真實面試成績或唯一技術選型。

## 追問順序

- 如果今天只讓客服手動跑一次報告，為什麼不先做 app-server UI？
- 同樣讀取 item 成功，為什麼整輪仍可能 failed？
- app-server 的 turn/completed 和 exec 的 turn.completed 可以交給同一字串判斷嗎？
- 工作台與 server 斷線，是否可以立即標失敗並重做？你還缺哪個觀察？
- cwd 指到教材目錄，是否就阻止讀取家目錄？read-only 是否只允許兩個檔案？
- 使用者核准一項命令，是否就核准客服關單？你會把什麼綁到核准要求？

## 常見弱答怎樣改善

| 弱答 | 改善方式 |
| --- | --- |
| SDK 比較簡單，app-server 比較厲害 | 補上「誰要處理歷史、串流及核准」，再說維護成本 |
| completed 就是完成 | 指出是哪個介面、哪個欄位、哪一層完成；用拆封未知反例 |
| Codex 都有安全機制 | 分別說檔案執行限制、外部工具權限及業務授權 |
| 沒看到關單文字，所以沒有關單 | 改查可用能力、完整動作紀錄與外部狀態 |

## 自評

四項各 0–2 分：需求是否明確、控制責任是否正確、能否分析失敗、驗收是否可觀察。0 為缺少，1 為概念，2 為有 T-1042 資料及證據。低分先修正一項，再重答；分數不是面試認證。
