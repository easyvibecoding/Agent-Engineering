# C07 · 分級提示

先自答。第一級找責任，第二級縮小缺口；需要解答時才開 solutions。

<a id="c07-q01"></a>

## C07-Q01

1. 先把「我怎麼顯示」和「工具在哪裡跑」分開。
2. 同一 thread 可有下一輪；資料更新仍要核對，thread ID 不能證明版本新鮮。

[回題目](README.md#c07-q01)

<a id="c07-q02"></a>

## C07-Q02

1. A 要不要自己接每個核准按鈕？B 需不需要讓產品成為通訊客戶端？
2. 把「能做到」與「值得先承擔」分開；SDK 也有不同語言與版本。

[回題目](README.md#c07-q02)

<a id="c07-q03"></a>

## C07-Q03

1. 最後一個事件的名稱和其中狀態是兩回事。
2. 「沒看到寫入事件」可支持本段紀錄未觀察到寫入；若紀錄可能不完整，不能外推整個系統沒副作用。

[回題目](README.md#c07-q03)

<a id="c07-q04"></a>

## C07-Q04

1. 把「不需要寫檔」和「允許讀哪些位置」拆成兩列。
2. 本機 sandbox 不會自動重設遠端服務帳號權限；需另檢查工具能力。

[回題目](README.md#c07-q04)

<a id="c07-q05"></a>

## C07-Q05

1. 先說需求是程式化使用 Codex，還是自訂客戶端，或自己編排流程。
2. 用「草稿完成但拆封未知」說明 harness 與業務驗收差異。

[回題目](README.md#c07-q05)

<a id="c07-q06"></a>

## C07-Q06

1. 先確定 trace 來自 exec 或 app-server，不能混接。
2. 斷線案應呈現狀態未知；沒有完整紀錄時，不要先標失敗再自動重做。

[回題目](README.md#c07-q06)
