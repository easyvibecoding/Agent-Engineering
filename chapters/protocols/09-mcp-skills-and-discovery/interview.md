# C09 · 面試與追問

先試說一分鐘：「工具選單看得到，為什麼可能讀不到工單？」不用先看下面所有追問。

## 兩分鐘短答骨架

題目：用客服例子說明 MCP 和 Skill 差別，如何搭配？先說需求和一次呼叫；順了再加拒絕與驗收。

1. **需求 20 秒：**兩個應用要共用店規能力，避免各寫一份轉接；單一應用未必需要 MCP。
2. **配置 35 秒：**MCP 接能力，Skill 放方法，AGENTS.md 放專案持續約定；host 管任務，client 通訊，server 提供與限制資料。
3. **具體路徑 35 秒：**讀 T-1042 r3 與 D14，得 12 天且拆封未知，產出詢問草稿。
4. **失敗與驗收 30 秒：**列舉不等於可讀，無權限不繞過；核對案件、規則與只讀邊界。

這是練習骨架，不要求背秒數。一次先修一段；合成案例不能說成自己的實作成果。

## 由淺入深的追問

請同伴或 Codex 每次只選一列，等你回答後再問下一列。表中右欄留作自評，不要一開始背答案。

| 追問 | 強答案應補什麼 |
| --- | --- |
| Resource 與 tool 都能提供 D14，怎麼選？ | 固定文件與條件查詢的互動差別，而非誰比較進階 |
| Skill 裡有腳本，是不是就能做事？ | 還缺執行環境、輸入及授權；有檔案不是執行證據 |
| 300 個工具縮到 2 個，如何知道沒漏？ | 正選與漏選測例、缺漏回報、受控擴大探索 |
| 列舉後權限被撤回怎麼辦？ | 每次執行仍驗權，快取不能放行 |
| 兩個 server 都叫 read_policy？ | 辨識 server、商店、來源及版本，不只比名稱 |
| 規格說有 Tasks，為何 app 沒有？ | 核心版本、必要能力、選用擴充與實際支援分開查 |

## 常見弱答如何改善

先挑最像自己口答的一列，只補一個具體動作再重答。

| 弱答 | 缺口 | 重答方向 |
| --- | --- | --- |
| 「MCP 就是 AI 的 USB。」 | 沒有角色、錯誤與授權 | 補一次 T-1042 呼叫與拒絕分支 |
| 「Skill 可限制所有權限。」 | 混淆方法與資料權限 | 指出 host 的執行政策與 server 的案件檢查 |
| 「工具越多越好，向量搜尋即可。」 | 沒有漏選或同名風險 | 用錯分類與錯商店測例說明如何發現 |
| 「我會看最新文件。」 | 沒有實際相容項目 | 說出共同協定版本、必要能力、選用擴充及測例 |
