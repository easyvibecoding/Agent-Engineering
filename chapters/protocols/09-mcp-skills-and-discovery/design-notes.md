# 09 · 設計取捨與疑難

客服助理需要讀 T-1042 和 D14。團隊有 300 個工具，另寫一份『先算日期、再查拆封』的方法；有人以為把方法放進 Skill，就能自動讀取所有案件。

## 取捨 1：直接工具還是 MCP？

同應用內的小工具可先直接整合，溝通責任較少。

**什麼情況換做法：**多個客戶端要共用店規服務時，再衡量 MCP 的互通價值。

## 取捨 2：方法放專案文件還是 Skill？

只適用本 repo 的規則留在專案指引。

**什麼情況換做法：**跨任務重用且可按需載入的方法才包成 Skill；授權仍在執行層。

## 常見卡點：錯在哪裡，怎麼改

| 容易說出口的話 | 問題在哪裡 | 較可靠的做法 |
| --- | --- | --- |
| Skill 說可讀所有資料，就已授權。 | 文字方法不能建立真實存取權。 | 由工具依呼叫者權限拒絕不允許的案件。 |
| 工具列得出來，所以所有擴充都能用。 | 選單、版本和擴充支援不同。 | 記錄實際雙方版本與必要能力，缺少就明確停。 |

## 拿本章案例檢查

這能避免把所有問題都塞進 prompt 或 Skill：沒有工具就補能力，版本不合就解決相容，無權限就停止。下一步不再只剩『再要求模型努力一次』。 用[診斷題 Q03](exercises/README.md#c09-q03)檢查是否能指出具體錯誤，再以 Q04 說明自己的方案。答案若只剩「加強安全／優化流程」，補寫對象、條件與可觀察結果。
