# 09 · 疑難與設計理由

[正文](lesson.md) · [題目](exercises/README.md)

## 需要說得出理由的選擇

### 1. Skill 還是工具？

設計理由：可重用的方法與領域步驟放 Skill。

替代方案與改選條件：真正取資料或改狀態需工具；Skill 可指導工具使用，仍經授權與驗證。

### 2. 直接工具還是 MCP？

設計理由：同應用內的窄工具可直接整合，較少通訊責任。

替代方案與改選條件：多客戶端共用能力時 MCP 可改善互通，代價是版本、驗證與連線管理。

## 常見疑難

### 疑難 1：支援 MCP 就代表所有擴充都能用

列出協定版本、擴充與實際 runtime 相容矩陣。

### 疑難 2：Skill 的 allowed-tools 等欄位就是系統權限

支援度依實作，執行權限由 runtime 與工具檢查。

## 如何證明選擇有用

以本章案例固定資料與成功條件，只改一項設計；記錄結果、失敗與必要資源。替代方案不是一律較差：回答何時改選，以及你會觀察什麼。尚未執行的驗證清楚標為待驗證。
