# C09 · 參考解答

以下是教學推理，不是執行結果。每題 4 分只供自評；替代方案須保留同一份已知、未知與授權。

<a id="c09-q01"></a>

## C09-Q01

先定責任，再分類能力。Codex 作 host，保存只讀任務、管理模型 context、驗收草稿；client 是 host 內的通訊元件；server 提供政策與工單能力，並落實資料存取控制。read_policy 是 tool，D14 內容可作 resource，退貨判斷模板是 prompt。

同一份 D14 可由 resource 或查詢 tool 提供。前者著重直接取資料，後者可按申請日選版；需比較產品互動，不是三者只能擇一。拿到模板不代表讀過工單。

**分點判分：**角色位置正確 1 分；四項責任分明 1 分；三類能力舉例 1 分；資料取得與授權不混淆 1 分。

**可接受替代：**也可用自己的應用當 host；若將兩個 server 合併，只要通訊、資料權限與驗收責任仍清楚即可。

<a id="c09-q02"></a>

## C09-Q02

「先自答」是持續專案約定，留在 AGENTS.md；判斷步驟可封裝 Skill；讀工單由真實工具提供。服務端決定客服 A 可讀哪些案件；Skill 的 allowed-tools 支援依 runtime 而異，不會把資料權限放大。

只有方法沒有工具時，應回報缺少讀取能力，不能宣稱取得 T-1042。只有一個應用、兩個穩定函式，可以先直接整合；多個應用要共用時再考慮 MCP 的相容與維護成本。

**分點判分：**三類配置各正確共 2 分；權限與方法分開 1 分；提出直接整合的合理條件 1 分。

**可接受替代：**一次性短方法可放任務說明，不必立即包 Skill；要說明未來如何避免重複維護。

## C09-Q03

①只證明取得 read_ticket 描述。②證明本次讀取遭拒，沒有拿到工單欄位。③只是方法的任務前提，不會改變權限。④其他工單的資料不支持 T-1042 的包裝狀態。第一個無效推論是在把「必須讀到」當成可繞權依據；後續又以別案冒充本案。

下一步核對呼叫者是否為預期客服 A、案件 scope 與錯誤類別。若需正當授權，回報缺口並等待；不得換帳號、擴查無關案件來補答案。對外說「目前無法讀取 T-1042，因此拆封狀態未確認」，可提供明確標成範本的草稿，但不能假裝已完成個案判斷。停止條件是必要資料無合法取得途徑。

**分點判分：**逐事件證據範圍 1 分；指出擴權與錯案兩個錯誤 1 分；合法診斷與下一步 1 分；未知及停止說清 1 分。

**可接受替代：**若已有使用者合法提供的同案資料，可列為另一來源再判斷；需標來源與版本，不能把它說成失敗工具的成功結果。

## C09-Q04

第一階段依只讀任務查工單與店規領域的精簡目錄；第二階段載入選定候選的完整契約。以 server 身分區分兩個 read_policy，對回商店與生效日。找不到必要工具可受控擴大一次搜尋；仍缺少就回報能力缺口。

執行前核對：目標與作用範圍、完整輸入輸出契約與版本、呼叫者的本次授權、副作用與結果驗收條件。四個測例分別是正常找到兩個讀取工具、政策工具分類缺漏、參數變更後仍用舊契約、列舉後權限被撤回。最後一例必須拒絕，不因快取曾允許就放行。

只有 6 個穩定工具時，直接呈現完整契約可更簡單。比較正確選擇與漏選，再看 context 和延遲；300→8→2 本身不是效能證據。

**分點判分：**兩階段與缺漏分支 1 分；四項執行檢查 1 分；四測例有可觀察結果 1 分；小選單替代與評估理由 1 分。

**可接受替代：**固定分類路由或使用者先選工具領域皆可；不要求用向量搜尋、第二個模型或特定 hosted tool_search。

## C09-Q05

可用骨架：「我們有兩個客服介面要共用店規查詢。MCP 約定應用與服務如何交換能力要求；Skill 是查有效規則、算日期、補問拆封的方法；AGENTS.md 保留本教材先讓讀者自答的持續約定。以 T-1042 為例，host 經 client 呼叫 server 的只讀工具，得到 r3 與 D14，寫出日期符合、拆封未知的草稿。若 server 拒絕讀取，Skill 不會替我取得權限，我會保留未知並回報缺口。驗收看同案版本、條件引用和沒有越權。」

追問短答：「列舉是看到能力描述；呼叫還有目標、身分與權限檢查。選單成功不是這張工單讀取成功。」

**分點判分：**需求與三種載體 1 分；角色與呼叫具體 1 分；拒絕分支 1 分；可觀察驗收且不誇大成果 1 分。

**可接受替代：**可從普通函式談起，說明當前未必需要 MCP；有清楚需求、限制與驗收，比背完所有擴充更重要。
