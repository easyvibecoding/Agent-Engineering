# C09 · 參考解答

這是可接受的推理範例，不是唯一措辭。其他方案若前提清楚、符合資料與權限且能驗收，也可成立。以下皆為教學分析，不是實際執行結果。

<a id="c09-q01"></a>

## C09-Q01

Codex 是 host，內部 client 連政策 server；tool 可查店規，resource 可提供已授權文件，prompt 可提供判斷模板。是否讀得到 D14 仍由服務與 runtime 授權控制，不由協定名稱決定。

**核對重點：**角色與能力類型分開；不把協定當授權。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C09-Q02

不代答屬專案指引；可重用判斷步驟可放 Skill；讀工單由受限工具提供。沒有工具就無法真正讀取，只能指出能力缺口；不能把方法文件當成讀取已成功。

**核對重點：**三者配置合理；說明方法不能產生能力或權限。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C09-Q03

先核對呼叫者與工單授權及具體錯誤；無權限就停止或取得正當授權。Skill 的必須不會擴權。若是版本／能力錯誤再查相容矩陣，不能每種失敗都改參數重試。

**核對重點：**不繞過權限；查呼叫者、範圍與錯誤。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C09-Q04

先從精簡目錄找工單與政策工具，再載入詳細輸入輸出契約；執行前依授權、目標與業務條件檢查。評估誤選、漏選與資源；找不到必要工具要明確回報，不猜一個名字。

**核對重點：**有目錄與詳細契約兩步；探索不等於核准。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C09-Q05

MCP 幫應用接到政策服務；Skill 教先查版本、算日期再確認拆封。兩者搭配仍需 server 真有工具且呼叫獲准；不會因套上 Skill 就讀到其他部門附件。

**核對重點：**溝通與方法分開；附真實執行限制。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C09-Q06

章內提供本機服務規格與假資料；驗收列舉不冒充可用性、合法讀取得到 D14、拒絕越權，版本或必要能力缺失就停，server 暫時失敗有限處理。沒有實際啟動就標規格而非通過。
