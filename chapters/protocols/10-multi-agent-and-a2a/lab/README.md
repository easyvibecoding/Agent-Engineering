# C10 · 未來 Lab 規格

狀態：**僅規格，未建立程式、安裝環境或執行。**

先只寫紙上規格：選兩個方案、填一個正常案例、再加一個失敗案例。以下表格可分次填，空白保持「待定」，不要填成已通過。

## 目的與獨立輸入

比較單 Agent 與 coordinator+A+B 是否能交出同樣可靠的條件式草稿；不以 Agent 數量判定成敗。

本 lab 未來自帶假資料：T-1042 r3，10/08 至 10/20 差 12 天、拆封未知；D14 自 10/01 取代 D07，要求 ≤14 天且未拆封。兩組用同一資料快照、只讀工具、模型設定與全隊總預算，不依賴前章程序或登入狀態。

## 產物契約

| 產物 | 必須包含 |
| --- | --- |
| 委派表 | 任務 ID、精確目標與版本、讀取範圍、停止規則、回報位置、驗收者 |
| worker 筆記 | 實際 ID/版本、事實、來源、未知、工作狀態、副作用 |
| 主草稿 | 日期符合、拆封待問；未寄送／關單／退款 |
| 對照報告 | 各案例狀態、品質、整隊資源、全程時間、失敗與返工 |

主草稿只由總負責者維護；分支筆記獨立。若未來選共編，規格需另寫 ownership、基底版本與衝突處理。

## 合成案例與預期驗收

| 案例 | 預期行為 |
| --- | --- |
| 正常 r3 | 兩份來源支持條件式草稿，業務仍等待資料 |
| B 回 T-1043 | 拒收錯目標分支，不能混入主稿 |
| A 漏拆封條件 | 補查 A，不能直接判定可退 |
| worker 失敗或逾時 | 保留失敗，依預算補查或交未完成 |
| B 回新版本 | 明列版本差異，由總負責者依問題決定快照或更新分析 |
| 兩人寫主稿衝突 | 阻止無責任的覆蓋，整合後讀回內容 |

這些是預期結果，不是已通過的測試。

## 比較與停止契約

先決定「品質怎樣才算合格」，再選資源指標，最後填達限行為。這個順序避免只因某支很快，就忽略它交的是錯工單。

品質至少三項：ID/版本正確、D14 條件完整、未知與權限表達正確。資源至少兩項：開始到可用產物的全程時間、全部 Agent 推論與工具用量。另分列整合錯誤，不把失敗案刪掉美化平均值。

全隊預算須包含總負責者、worker、返工和重試；預先填限制值及達限行為，不在執行中無限加碼。達限留未完成與原因，不能把 worker 結束標成整題通過。

事件欄位至少有 run_id、task_id、角色、目標及版本、開始/結束、狀態、來源、產物位置、驗收結果與拒收原因。實際結果待後續授權實作才填寫。

目錄獨立不等於程序、檔案或網路 sandbox，也不隔離共用訂閱額度。推論優先訂閱路線，實際資格、並行限制及能力另驗證。
