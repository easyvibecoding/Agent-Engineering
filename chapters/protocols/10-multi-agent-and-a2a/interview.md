# C10 · 面試與追問

## 主問題與短答骨架

**多 Agent 為什麼可能更差？**先用自己的話答兩分鐘，再對照骨架：

1. **選擇：**先找夠長且獨立的工作，A 查政策、B 讀工單可以並行；整合不能提前。
2. **因果鏈：**委派沒綁 ID/版本 → worker 交錯資料 → 共寫主稿覆蓋 → completed 被當驗收，最後交出錯結論。
3. **控制：**獨立筆記、主稿單一責任者、核對來源與完整條件，缺資料則補查或等待。
4. **比較：**同題、同權限、同全隊預算，量品質、全程時間及整隊資源；不划算就回單 Agent。

這是組織回答的方法，不是要背的唯一說法；口答必須保留 T-1042 r3 拆封未知、只能交草稿。

## 追問順序與判斷目的

| 追問 | 想確認什麼 |
| --- | --- |
| A=25、B=30、整合=8，為什麼不是 25 秒完成？ | 理解最慢分支及整合依賴 |
| B 回 T-1043 或 r4，你如何處理？ | 目標拒收與版本契約不同 |
| 多一位審查者為何仍可能錯？ | 共享盲點與獨立證據的差別 |
| A 的結果回來後誰繼續？改用 handoff 有何不同？ | 控制權和最後責任 |
| 你說用了 A2A，所以安全了嗎？ | 協定、能力宣告與授權不混淆 |
| 哪個觀察會讓你停用多 Agent？ | 能以品質、整合成本作決策 |

## 常見弱答如何改善

- 「溝通成本高」：補一件事，例如漏寫 revision 造成重查，再說如何在產物裡檢查。
- 「多開幾位互相驗證」：補具體檢查清單及異議交給誰處理；不能只做同意投票。
- 「平行後省一半」：重算 63／38，列理想條件，分開全隊資源；不要推導未量到的費用。
- 「我做過很強的多 Agent」：若只有本教材規格，改說「我設計了對照與驗收」，不能冒充真實成果。

## 自評

每項 0–2 分：具體因果鏈、可驗收委派、失敗處理、全隊公平比較。0 缺少，1 只有概念，2 有本例資料及可觀察結果。這只供練習，不代表通過真實面試。
