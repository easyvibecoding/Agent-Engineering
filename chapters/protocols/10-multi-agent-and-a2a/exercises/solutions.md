# C10 · 參考解答

這是可接受的推理範例，不是唯一措辭。其他方案若前提清楚、符合資料與權限且能驗收，也可成立。以下皆為教學分析，不是實際執行結果。

<a id="c10-q01"></a>

## C10-Q01

當工具呼叫時主 Agent 收結果後繼續；handoff 由另一助理接一段互動；A2A 是不同 Agent 系統的互通方式。無論選哪種，都要明定誰驗收案件、版本與產物。

**核對重點：**控制與通訊分開；說出結果驗收者。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C10-Q02

串行 25+30+8=63 秒，理想並行 max(25,30)+8=38 秒。這忽略啟動、排隊、重複工作與整合錯誤；真實比較要量測，不能直接把 25 秒差當固定可省時間。

**核對重點：**算出 63／38 秒；說明理想假設及額外成本。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C10-Q03

先取得各自查證範圍、ID、版本、來源與未知，再整合。委派改為獨立子題與獨立筆記，主稿由 coordinator 寫；任務不能因 worker 結束就標全部驗收通過。

**核對重點：**不直接採信；補責任、產物及驗收。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C10-Q04

指定只讀 T-1042，回傳案件 ID、revision、日期、拆封狀態、來源位置及未知／失敗；禁止寫主稿或關單。Coordinator 驗收時對回目標，若回的是 T-1043 就不採用。

**核對重點：**有精確目標、只讀範圍、產物與驗收要求。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C10-Q05

每個 worker 都帶重複 context、競爭配額或覆寫主稿，可能讓整體更慢且難查錯。先拆獨立工作，以同任務、總資源和成功標準比較，觀察整合錯誤與完整時間，而非只看某支很快。

**核對重點：**至少一條因果鏈，及公平比較方式。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

[回題目](README.md#c10-q05)

<a id="c10-q06"></a>

## C10-Q06

以同批工單比較單 Agent 和分工，檢查目標／版本正確、條件完整、未知誠實；量總推論／工具資源與全程延遲。保留 worker 失敗和整合錯誤，不刪掉難題美化結果。

**核對重點：**條件可比較；worker 失敗不冒充通過。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。
