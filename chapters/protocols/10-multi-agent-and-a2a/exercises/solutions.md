<a id="c10-q01"></a>

## C10-Q01

agent-as-tool 讓主 Agent 保持控制；handoff 交出部分控制或互動；A2A 為系統間互通。可以組合使用，但必須明確狀態與驗收責任。

**自評：**交付三項區分及責任流。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c10-q02"></a>

## C10-Q02

獨立分支較適合並行；相依鏈不會因增加 worker 消除等待。先拆出真正獨立子工作，再比較總時間、資源與成果，不以子 Agent 數量判定效率。

**自評：**交付相依圖與比較指標。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c10-q03"></a>

## C10-Q03

缺少主題／檔案責任、單一寫入者、來源去重與結果驗收。改交獨立產物，由 coordinator 確認證據與衝突後整合；保留未驗證部分。

**自評：**交付四項契約修正。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c10-q04"></a>

## C10-Q04

委派含 task ID、owner、輸入、範圍、工具、產物與完成條件；回報含已確認結論、來源、查過範圍、未知與失敗原因。可接受表格或文件，重點是可驗收。

**自評：**交付可直接交接的契約。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c10-q05"></a>

## C10-Q05

可能重複查找、丟失交接脈絡、競爭共享狀態與額度，整合也需時間。用同任務與限制比較成功率、critical path、總資源及重複工作比例。

**自評：**交付因果與比較方式。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c10-q06"></a>

## C10-Q06

同批研究題，單 Agent 與三 worker 方案使用同資料和總資源上限；評估引用、衝突、重複工作與延遲。worker 失敗時檢查是否保留部分結果與未知，禁止由狀態冒充成果。

**自評：**交付對照、觀測與失敗案例。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
