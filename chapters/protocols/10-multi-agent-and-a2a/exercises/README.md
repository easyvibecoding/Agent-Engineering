版本：2026-10-21，細化題內步驟，保留題號。以下均為合成案例，可獨立作答。

固定輸入：T-1042 r3，2026-10-08 到 10-20 差 12 天；D14 自 10/01 取代 D07，要求 ≤14 天且未拆封，r3 拆封未知。只讀並寫草稿，不准寄送、關單或退款。

## C10-Q01 · 概念重建

以查 D14 的專家為例，比較 agent-as-tool、handoff、A2A。主助理只需要一份政策筆記；另一個變體中，專家需要接續向使用者詢問三輪。

**先做：**選一個情境，寫誰接著處理、誰檢查結果。

**再做：**替另一情境選方案並說明原因。加深時再解釋 A2A 為何能與兩者組合。

## C10-Q02 · 方案比較

合成時間 A=25 秒、B=30 秒、整合=8 秒，A/B 可獨立開始。計算串行及理想並行。另一算例：單 Agent 輸入 6,000 tokens；A/B 各 4,000、總負責者 2,000。

**先做：**只算串行與理想並行的等待，列計算式。

**再做：**合計全隊輸入量。加深時列兩個讓收益消失的原因；不要把 tokens 當訂閱費用。

## C10-Q03 · 軌跡診斷

合成事件：A、B 都說 completed 且未交來源。A 先寫主稿「依 7 天規則已拒絕」，B 後寫「T-1043 可退貨」，覆蓋了 A。原任務仍是 T-1042 r3、D14、只讀及草稿。

**先做：**各指出 A、B 哪裡對不上原任務；寫下一步先停什麼。

**再做：**各寫一句要他們補交什麼，再指定誰能寫主稿。加深時分開「稿件宣稱」與「實際操作」，說明還缺哪種證據。

## C10-Q04 · 架構設計

寫給 B 的委派：只讀 T-1042 r3，取得日期及包裝資料，禁止改主草稿或工單。變體一：回報 T-1043；變體二：實際已是 r4。

**先做：**寫一小段委派，至少包含五個回報欄位。

**再做：**處理錯 ID，說明何時停止。加深時再處理 r4：由誰決定分析快照或最新狀態？

## C10-Q05 · 面試口答

用本章案例回答：多 Agent 為什麼可能更差？你只有兩分鐘，請選一條具體失敗因果鏈，並提出公平驗證方式。

**先做：**用一分鐘講一條「哪裡出錯 → 怎樣讓結果更差」的因果鏈。

**再做：**補你會怎麼比較兩方案，以一項品質、兩項資源觀測支持；總長控制兩分鐘。

## C10-Q06 · 未來 Lab 規格

只設計單／多 Agent 對照，不建立程式。兩組均用相同 T-1042 r3、D14、D07 假資料與只讀工具；加入錯 ID、漏條款、worker 失敗和主稿衝突。
