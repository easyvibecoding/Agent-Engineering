# C14 · 面試與追問

## 兩分鐘主問題

你會如何打造可靠的客服 Agent？以 T-1042 r3 為例：相差 12 天，D14 要求 ≤14 天且未拆封；包裝未知，只准判斷與草稿。

先口答，不先讀參考解答。這是模擬面試，不是真實面試成果。

| 時間 | 短答骨架 | 至少說出一件具體事 |
| --- | --- | --- |
| 0–20 秒 | 使用者結果與範圍 | 草稿；不寄送、關單、退款 |
| 20–60 秒 | 資料到判斷的路徑 | r3＋D14；12 天符合但包裝未知 |
| 60–90 秒 | 失敗與責任 | 錯 ID 不用，越權由工具層拒絕，缺資料補問 |
| 90–120 秒 | 驗收與取捨 | 四類案例與雙層狀態；先單一 Agent |

## 十分鐘怎麼展開

1. **需求 1 分鐘：**誰用？哪些政策？只有草稿嗎？若面試官要求退款，先指出範圍變更。
2. **資料與路徑 2 分鐘：**目標 ID、版本、有效日、條款位置、未知如何進入 context。
3. **決策與狀態 2 分鐘：**何時再讀、何時停止、怎樣分本輪完成與業務完成。
4. **風險與恢復 2 分鐘：**舊規則、注入、越權、讀取失敗；寫入若另授權，新增哪些恢復責任。
5. **驗收 2 分鐘：**每種風險配故障輸入、可觀察結果；成功率分母、未跑與中斷分開。
6. **取捨與成果 1 分鐘：**現在不需要哪些元件；何種需求再擴充；哪些只設計、哪些真的跑過。

十分鐘是展開順序，不是硬性秒數評分。被打斷時先回答追問，再接回資料路徑。

## 常見追問與弱答修正

| 面試官追問 | 常見弱答 | 改善方向 |
| --- | --- | --- |
| 為何不用多 Agent？ | 單一比較簡單 | 指出資料少、任務短，列協調代價與換方案條件 |
| 怎麼知道沒有退款？ | prompt 寫了不准 | 指出執行權限與實際副作用證據；光看草稿不足 |
| 都完成了為何還問客戶？ | 模型不知道 | 分開草稿完成與案件待資料，未知本來就是狀態 |
| 工單變 r4 怎麼辦？ | 用記憶接續 | 重讀來源版本；明示 r4 變體後重新判斷 |
| 這專案成功率多少？ | 預計有九成 | 目前只有設計；若是目標，要說如何量、還沒達標 |
| 換成研究助理？ | 換 prompt 即可 | 保留證據與未知原則，重設來源可信度與結論驗收 |

## 自評與重練

四項各 0–2 分：需求與邊界、具體資料路徑、失敗責任、驗收與取捨。0 為沒說，1 為只有名詞，2 為本例可核對的說明。流暢不抵消錯誤核准或越權。

先錄下第一版，選最低一項重講 30 秒，再重講完整兩分鐘。不必把口答改成背稿。需要時才看 [Q05 參考解答](exercises/solutions.md#c14-q05)。
