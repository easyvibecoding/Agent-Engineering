## C14-Q02 · 方案比較

方案 A：單一 Agent 明確讀取一筆工單與有效店規。方案 B：兩個 worker 分讀工單與店規，再由整合者寫草稿。現在資料很少，沒有延遲實測。

**先做：**選初版方案，用一項收益與一項代價說明。

**加深：**再提出一個值得換方案的需求變化，說怎樣公平比較。

**交付與判分：**交付選擇表與換方案條件；不能虛構 B 更快或成功率更高。

## C14-Q03 · 軌跡診斷

審查以下設計稿，每次只處理一行：

1. 查詢目標 T-1042，但來源註記 T-1043 r3。
2. r3 包裝未知，結論「日期 12 天，所以已核准退貨」。
3. 工具清單僅讀取，但草稿寫「已退款」。
4. 以 turn/completed、turn.status=completed 當退款成功證據。

**先做：**一次只處理一行：圈出不成立的宣稱，再寫修正動作。

**加深：**四行都做完後，補每行還缺哪種證據。

**交付與判分：**四行都要處理；即使技術完成，也沒有業務操作證據。不要為補證據而擅自執行退款。

## C14-Q04 · 架構設計

**先做：**沿正文寫一頁草稿：需求→資料→判斷→交付，旁邊標出誰負責。

**再補：**加入正確 r3 缺資料、暫時讀取失敗、候選關單三分支，以及內容驗收不過的有界修正。

**加深：**至少四個風險各配驗收；每個元件回答「拿掉會出現什麼錯」。

**交付與判分：**交付一頁表或圖加表；有具體預期結果，且不為了滿圖加入無需求元件。
