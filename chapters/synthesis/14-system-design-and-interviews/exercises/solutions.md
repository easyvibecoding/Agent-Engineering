# C14 · 參考解答

[回題目](README.md)

請先自答再閱讀。以下是可辯護的參考方案；只要假設、權限、取捨與驗證一致，也可接受其他設計。

<a id="c14-q01"></a>

## C14-Q01

例如工單助理為客服提供建議；輸入為案件和政策；成功是核准後精確關閉並讀回；限制是不能自行退款；主要風險為錯目標和重複副作用；以狀態與軌跡驗收。

**自評：**交付六項且彼此一致。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c14-q02"></a>

## C14-Q02

固定可預測流程先用 workflow；需研究控制可自建 harness；重點在工具與產品整合可用 Codex。以任務分支、可觀測性、恢復責任與實測資源作選擇，列出改選條件。

**自評：**交付三方案取捨與選擇。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c14-q03"></a>

## C14-Q03

來源過期造成錯結論，目標未綁定造成核准替換，恢復未讀回造成重複副作用。各加入版本衝突、目標被換與提交後斷線測試，確認實際資料與狀態。

**自評：**交付三條因果鏈及測試。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c14-q04"></a>

## C14-Q04

一頁中連接使用者授權與工具邊界，以持久狀態支撐恢復，驗收最終結果與 trace。發布先限讀／限使用者，失敗回到人工或只讀。替代設計只要責任清楚即可。

**自評：**交付一頁完整設計與兩項取捨。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c14-q05"></a>

## C14-Q05

回答先確認需求與授權，再解釋推論和 harness 分工，補工具、狀態與評估。遇到不確定的帳號能力明確待驗證，不臆測可用性或虛構實作成績。

**自評：**交付兩分鐘主答與三輪有因果的追問回答。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c14-q06"></a>

## C14-Q06

章內自帶資料與環境，選定一個推論入口；驗收正常、拒絕、逾時未知、取消與恢復，列產物和讀回。證據分為已觀察、待驗證與未知，不把設計稿標為已部署。

**自評：**交付自包含契約、五類案例與狀態標記。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
