# C02 · 參考解答

[回題目](README.md)

請先自答再閱讀。以下是可辯護的參考方案；只要假設、權限、取捨與驗證一致，也可接受其他設計。

<a id="c02-q01"></a>

## C02-Q01

prompt 為指令；context 是當輪全部可見輸入；memory 是跨步驟保存並可再取用的資訊。筆記檔可作 memory，讀入其摘要才進入 context。

**自評：**交付三項定義與資訊流向。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c02-q02"></a>

## C02-Q02

先保留任務與限制，再選最新且直接支撐問題的段落，記錄來源與版本；冗長輸出只保留索引或摘要。比較引用正確率與工具往返，調整按需讀取策略。

**自評：**交付選取規則及品質／延遲驗證。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c02-q03"></a>

## C02-Q03

檢查引用位置存在且屬於目標版本；檢查內容是否支持結論；檢查題目要求與狀態是否滿足。schema 驗證繼續保留，不能替代這些檢查。

**自評：**交付三個不同層次的檢查。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c02-q04"></a>

## C02-Q04

交接包含目標、限制、決策、未解事項、已確認操作與證據位置；敏感例外條件與操作讀回需保留精確引用或 ID。可用表格或筆記，無須特殊向量庫。

**自評：**交付交接欄位與遺漏測試。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c02-q05"></a>

## C02-Q05

容量不等於資訊相關性，也不解決互相衝突或過期來源。比較同批問題的全量輸入與選取輸入，量測引用品質、漏答與延遲，才能判斷取捨。

**自評：**交付機制解釋與可反駁的實驗。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c02-q06"></a>

## C02-Q06

比較全量、固定摘要、按需讀取；使用相同問題與版本化文件，驗收正確結論、引用與資源。來源衝突與摘要遺漏是必要案例；不把某次輸出較短直接稱為省成本。

**自評：**交付控制變因、基準與案例。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
