# C02 · 面試與追問

## 主問題

「Context 很大，為什麼仍要挑選資料？」先用 D07／D14 口答兩分鐘。暫時遮住下方骨架，答不完整也先留第一版。

## 短答骨架

先說容量與適用性不同：兩版政策放得下，不代表知道哪版有效。

再落到 T-1042：本輪帶 r3、日期、拆封未知、D14 完整條件與取代關係；歷史留回查位置。

最後補代價與驗證：按需讀多一次往返，摘要可能漏條件；固定來源、問題與模型設定，比較錯版、漏條件、未知與完整時間。這是評估設計，尚無實測結果。

## 追問階梯

一次只選一題，等答完才問下一題。

- 只有五段資料，你會先保留哪段？再追問它支撐什麼決定。
- JSON 已合法，你還查什麼？再追問那句話的來源。
- 摘要可能失真，為何仍用？再追問何時回原文。
- 任務改成政策比較，D07 還刪嗎？再追問選取條件如何改變。
- 怎樣證明策略較好？再追問固定什麼、留下哪些結果。

## 常見弱答如何修

「做 context engineering。」把名詞換成一個動作：「把 D14 生效資訊與未拆封條款一起帶入。」

「壓短能省一半成本。」先縮小主張：「要量載入與補讀總量，再分開比較時間與配額／費用，不能從字數推定比例。」

「用 JSON 避免幻覺。」改成可查的檢查：「先驗欄位合法，再回 r3 找未拆封證據。」

## 自評與誠實表述

只挑本次最弱的一項重答：是否有具體錯例、採用條件、代價、可觀察驗收。每項可給 0–2 分：沒答／只有概念／落到案例。分數供練習，不代表真人面試成果。

還沒執行，就說「我設計比較三種資料袋」，不要說「已證明準確率提升」。需要時才看 [Q05 參考解答](exercises/solutions.md#c02-q05)。
