# 01 · 疑難與設計理由

[正文](lesson.md) · [題目](exercises/README.md)

## 需要說得出理由的選擇

### 1. 固定流程還是自主選路？

設計理由：證據來源與步驟已知時先用固定流程，較容易驗證與計算資源。

替代方案與改選條件：任務分支受中間結果影響且人工難以列舉時，可讓模型在受限工具集內選路。

### 2. 先做通用 Agent 還是窄任務？

設計理由：窄任務較容易定義輸入與可觀察的成功狀態。

替代方案與改選條件：需要多種任務時，先共享工具與驗收介面，再以 eval 判斷是否值得統一控制器。

## 常見疑難

### 疑難 1：把模型回答當成執行結果

查目標狀態與工具回傳；文字表態只能證明模型輸出了那句話。

### 疑難 2：把有工具的聊天介面全部叫自主 Agent

說明誰決定下一步與何時停止，避免只有名詞而沒有責任。

## 如何證明選擇有用

以本章案例固定資料與成功條件，只改一項設計；記錄結果、失敗與必要資源。替代方案不是一律較差：回答何時改選，以及你會觀察什麼。尚未執行的驗證清楚標為待驗證。
