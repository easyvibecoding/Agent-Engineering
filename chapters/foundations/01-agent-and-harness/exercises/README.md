## C01-Q01 · 概念重建

把四個工作分給適當角色：算出 12 天、建議追問拆封、實際讀 T-1042 r3、拒絕關單。再補上 runtime 與 environment 各提供什麼。

**交付與判分：**交一張「工作／負責者／可觀察證據」表。模型可以提出哪個要求？哪個動作必須由實際程式執行？用一句話區分 Agent 與固定 workflow。

## C01-Q02 · 方案比較

任務 A 是把 CSV「姓名」欄改成 name；欄名衝突一律回報。任務 B 是判斷 T-1042；資料只含兩個日期與包裝欄位，缺欄位一律產生固定詢問。變體 B2 才加入不固定的附件類型與來源選擇。

**交付與判分：**為 A、B、B2 各選固定流程、模型單步或有限 Agent，說明原因、代價，以及什麼觀察會讓你改選。不能只因 B 是客服文字就選 Agent。

## C01-Q03 · 軌跡診斷

另一張同樣只准草稿的教學工單有四筆合成紀錄：e1 任務=只產生草稿；e2 工具清單只有讀取與日期計算；e3 產物=reply-draft；e4 模型最終回答=「已寄送回覆」。沒有寄送工具事件，也未查外部郵件系統。

**交付與判分：**寫給客服的更正訊息；列出已證明、未證明、禁止補做各一項；指出要查哪種證據才能確認是否由其他流程寄出。定位是交付內容錯、授權錯還是外部寫入錯，證據不足時保留未知。

## C01-Q04 · 架構設計

為 T-1042 畫責任圖，至少有任務、模型、工具、執行前授權與交付檢查。輸入可有兩種：A 已附 r3 與 D14；B 尚未提供，需先讀取。

**交付與判分：**圖須容許 A 不呼叫工具、B 讀取後回流。標出資料缺漏時的停止點，以及模型不能自行決定的兩件事。另列兩個能查出圖畫錯的測試情境。

## C01-Q05 · 面試口答

用 T-1042 回答：「模型很強，為什麼還需要 harness？是不是所有工作都應該做成 Agent？」

**交付與判分：**準備 90 秒口答：白話定義、一次候選到執行的過程、一個控制失敗、驗收證據、何時選固定流程。最後一句分開草稿完成與退貨未定。
