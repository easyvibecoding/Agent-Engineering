# 01 · Agent 與 Harness 全貌

你接到一句「先幫我寫草稿」，模型卻說「我會讀工單」。這句話離真的交差還有多遠？從這個小縫隙開始，本章帶你分清楚誰提議、誰做事、誰查證。

## 前置與跳章入口

先打開[正文](lesson.md)，跟著五個步驟讀到「本章驗收」。不需要 API、OAuth 或程式環境；能讀懂兩個日期和「而且」條件就能開始。

這是全課的合成客服案例。若你從別章跳來，只要記得：T-1042 r3 相差 12 天，店規要求 ≤14 天且未拆封，包裝未知；此輪只交草稿。詳細資料在正文可展開核對，不用先背 ID。

## 核心讀法：今天交出兩張東西

第一輪讀到正文「本章驗收」就停，約 40–45 分鐘。後面的流程圖、角色全表和來源可以略過。

接著先做[Q01](exercises/README.md#c01-q01)：把工作分給負責者。做完再選 Q03 診斷紀錄，或 Q05 練 90 秒口答。14 天路線做 Q01、Q03、Q05；7 天路線先做 Q01、Q05。

卡住時，回正文找你分不清的那一步。仍不清楚，再讀[設計取捨](design-notes.md)或開一級[提示](exercises/hints.md)。先修自己的答案，需要時才讀[參考解答](exercises/solutions.md)。

核心連同自答與修正約 2–3 小時。今天留下責任表和條件式草稿即可，延伸不必一次做完。

## 深挖讀法：第二輪再做

想畫架構，再讀正文深挖區與 Q04。想比較方案，讀設計取捨第一項與 Q02。想準備面試，用[面試追問](interview.md)一次補一個弱點，或把自己的答案附給[Codex](codex.md)。

[Q06 與 Lab 契約](lab/README.md)只寫未來規格。本章沒有建立程式、環境或真實執行紀錄。

## 如何知道自己懂了

暫時關掉正文，試說：「模型提議以後，真正執行由＿＿負責；我能交出＿＿，但還不能說＿＿。」你若能用工單資料補完，比背完五個英文名詞更有用。

中斷前留一句：我卡在＿＿；下次從正文的＿＿或 Q＿＿接讀。個人筆記可放 repo 的 .study/。
