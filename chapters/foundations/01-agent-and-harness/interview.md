# C01 · 面試與追問

面試官把問題丟過來：「模型都這麼強了，為什麼還需要 harness？」先別在腦中排全部術語。從你這次到底答應交什麼開始說。

## 主問題與短答骨架

先自己答 30 秒，不開參考解答。能說清 harness 在模型之外做哪件事，就先停。

第二次再延長到 90 秒。可以沿著這條路，而不是背逐字稿：

> 只交草稿 → 模型提出讀取候選 → 控制端檢查 → 工具回傳 → 用 12 天與包裝未知判斷 → 核對產物後交付。

若還有時間，補一句何時不用 Agent：固定欄位與缺漏分支已寫全，workflow 就夠。最後分開草稿完成與資格待確認。

這是合成案例的口答練習，不是實作成果或真實面試經歷。

## 追問梯度

一次只選一題。答完，先確認自己有沒有引用本例資料，再追下一題。

1. 「不用模型能做嗎？」先指出哪個分支已固定，不急著列更多技術。
2. 「模型建議關單但沒執行，算事故嗎？」先分候選與外部狀態，限定可觀察範圍。
3. 「資料都給了，還要讀取嗎？」讓已附資料的路可以跳過無用動作。
4. 「Harness 與 runtime 差在哪？」不只背定義，說出實際控制與運作由誰提供；範圍可能重疊。
5. 「你怎麼證明自主？」指向依中間結果改變下一步的紀錄，別擴大成所有情境都能做對。
6. 「草稿完成但資格未知，算成功嗎？」回到交付契約與業務狀態兩層。

## 常見弱答怎麼改

如果你說「harness 讓 Agent 安全可靠」，再補一個具體動作：在工具執行前拒絕關單，留下目標與原因。抽象定義才開始有可核對的內容。

如果你開始列 memory、MCP、多 Agent，先停一下。這些機制能補回哪一份缺少的證據？若說不出，就回到 r3 的包裝未知，不必用更多名詞掩蓋。

如果你想說「我已全部跑通」，先查自己的成果狀態。本 repo 只有 Lab 規格，就說已設計與已寫驗收；未實作、未測試的部分照實保留。

## 自評

每項 0–2 分：交付範圍、具體事實、責任與取捨、可觀察驗收。缺少是 0；只有名詞是 1；能用案例推理是 2。分數只供練習，不等於通過面試。
