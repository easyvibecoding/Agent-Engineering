# C01 · 面試與追問

## 主問題與短答骨架

「模型很強，為什麼還需要 harness？是不是所有工作都應該做成 Agent？」先閉起參考解答，口答 90 秒。

練習時按五句組織，而非背一段漂亮定義：

1. **交付：**本例只交 T-1042 草稿，非辦完退款。
2. **責任：**模型提出判斷／動作，執行控制接工具、檢查限制、保存結果與停止。
3. **事實：**12 天符合日期條件，包裝未知；不能跳成核准全部條件。
4. **失敗與證據：**若模型說已寄出，要查工具／外部紀錄；若要求關單，執行前應攔下。
5. **取捨：**分支固定時 workflow 就夠；需要依新內容選路才評估有限 Agent。

這是合成案例的口答結構，不是實作或真實面試經歷。

## 追問梯度

| 面試官追問 | 想看什麼 | 回答要落在哪裡 |
| --- | --- | --- |
| 不用模型能做嗎？ | 能否避免過度設計 | 欄位、規則與缺漏分支若固定，可用流程加模板。 |
| 模型只建議關單但沒執行，算越權事故嗎？ | 是否分候選與副作用 | 記錄不當候選與攔截；不能直接宣稱真的關單。 |
| 資料都給了，還需要讀取工具嗎？ | 能否省掉無用步驟 | 驗證來源與必要資料後可直接判斷，不必儀式性呼叫。 |
| Runtime 和 harness 到底差在哪？ | 是否知道定義邊界 | 名稱可能重疊，應具體指出控制及實際運作由誰提供。 |
| 你怎麼證明有自主能力？ | 是否以事件而非名稱判斷 | 提供根據中間結果改變下一步的紀錄，並限定只是該次觀察。 |
| 草稿做完但資格未知，算成功嗎？ | 能否說清楚驗收層級 | 草稿契約可完成，資格仍等待資料。 |

## 常見弱答怎麼改

| 弱答 | 為什麼不足 | 改善方向 |
| --- | --- | --- |
| Harness 是讓 Agent 更安全可靠的框架。 | 用抽象詞解釋抽象詞 | 說出誰拒絕關單、何時檢查、留下什麼事件。 |
| LLM 有推理能力，所以不需額外控制。 | 推理不會自動執行或限制工具 | 走一次候選→驗權→工具→結果的過程。 |
| 我會加 memory、MCP 和多 Agent。 | 沒說哪個缺口需要哪個機制 | 先回答 r3 包裝未知，新增機制能帶來哪份證據。 |
| 我做過的系統全部跑通。 | 本 repo 沒有 Lab 執行證據 | 依實際狀態說設計過、規格已寫；未實作不要冒充成果。 |

## 自評

每項 0–2 分：交付範圍、具體事實、責任與取捨、可觀察驗收。0 分缺少；1 分只有名詞；2 分能引用本例推理。只供練習，不代表通過真實面試。
