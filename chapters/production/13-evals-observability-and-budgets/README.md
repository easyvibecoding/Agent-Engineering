# 13 · Evals、Observability 與資源

章節 ID：C13 · 內容修訂：2026-10-21 · 約 2–3 小時 · Lab 僅規格，尚未實作。

## 這章要解決什麼

**怎麼知道 Agent 真的變好，而不只是回答變順？**

前章提出恢復機制，本章用可重複的案例與事件驗證它，也檢查品質、延遲和預算。

本章交付：一份包含六案狀態、兩種分母、失敗原因與下一步的合成評估報告。

## 跳章入口

以下全部是合成評估資料，沒有實際模型測試：預定六案，A 正常、B 條件缺漏、C 越權阻擋通過；D 過期店規失敗；E 配額中斷未評分；F 尚未執行。

這是虛構教材案例，不是法律建議、真實客服紀錄或執行證據。完整設定見[共同案例](../../../maps/course-story.md)。 不要求先完成前章練習或啟動任何環境。若名詞陌生，可先讀正文的白話對照，再回查[詞彙表](../../../maps/glossary.md)。

## 具體前置與讀法

先能分辨第 03 章的工具結果與實際效果，以及第 12 章的「結果未知」與「明確失敗」。不熟可跳回對應正文；不用完成 lab。只懂百分比即可算本章核心，延伸不要求統計公式。

**核心約 2–3 小時：**讀正文六案、rubric、分母與 D 事件追查，交一張狀態表和一段報告；做 Q01／Q03／Q05，再口答修正。先不讀 hints／solutions。

**深挖另排 30–60 分鐘：**讀重複試跑、grader 校準與資源表，做 Q02／Q04；Q06 只寫驗收契約。分層讓第一輪先能準確報告，再處理「如何相信評分器」與比較設計。
