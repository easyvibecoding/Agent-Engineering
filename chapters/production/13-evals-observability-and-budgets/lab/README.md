# C13 · 未來 Lab 驗收契約

狀態：**僅規格，未建立程式、安裝環境或執行。** 不填寫模型通過成績。

## 要比較什麼

使用 [正文 A–F](../lesson.md#把六張考卷放到桌上)，每方案每案預定三次，共 18 次；兩方案共 36 次。固定同一考題集、輸入版本、rubric 及權限；比較模型時固定 harness，比較 harness 時固定模型。多因素一起改則只比較整體方案。

A 是明示未拆封變體；B 是拆封未知；C 是無權寫入；D 是新舊店規；E 測中斷狀態處理；F 使用另行核准的關單已完成／回覆遺失變體。F 不授權其他案寫入。每案自帶假資料，不讀真實工單或憑證。

## 輸入與輸出契約

| 類型 | 必填內容 | 缺少時怎麼做 |
| --- | --- | --- |
| 試跑計畫 | 方案、案例、版本、預定次數、時間／輪數／工具上限 | 不開始比較 |
| Trial 記錄 | 唯一 ID、開始／終止狀態、原因、來源與工具證據、產物位置 | 對應結論標缺證 |
| 評分記錄 | rubric／grader 版本、逐項判定、證據、人工分歧 | 記未評分或評分缺口 |
| 比較報告 | 每案所有 trial、通過／失敗／中斷／未跑、分母、時間與限制 | 不報全面通過 |

## 停止與公平性

啟動前填具體上限；本規格不猜測帳號可用配額。達上限或配額中斷時保留紀錄並停止；後續重排用新 trial ID，不能覆寫原次或悄悄用成功次替代。方案間若可執行數不同，揭露缺口，不挑容易題比平均值。

訂閱路線先確認資格與可用能力；不自動 API key fallback。目錄獨立不會分開帳號共用配額，執行前另安排並行度與排程。

## 未來的具體驗收

- 讀入合成狀態 A/B/C 通過、D 失敗、E 中斷、F 未跑時，可重算 3/4 與 3/5，且不將 E/F 寫成品質失敗。
- D 的來源選版錯誤能追回同一 trial 的候選、選定來源與草稿；事件不含真實登入 token。
- 正確短答不因措辭差異被錯殺；引用 D14 卻忽略拆封／權限的答案不能通過必要項。
- F 能用原 operation_id 查已完成狀態；驗證實際只產生一次關單效果。這項在未來假環境執行，不以模型自述驗收。
- 修正後保留舊結果並列比較；若未跑全部回歸，報告明列未重驗案。

以上是驗收目標，全部尚待實作及執行。實際完成時需保存命令、輸入、事件與結果，不能用本頁規格代替證據。
