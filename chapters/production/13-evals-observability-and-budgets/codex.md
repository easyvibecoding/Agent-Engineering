# C13 · Codex 協作卡

目標是你自己能寫出評估結論，Codex 負責追問與找缺口。先附自己的答案，預設僅讀本章正文、設計取捨及題目；要求提示／解答時才讀對應檔案。不建立 lab、不修改全域設定。

## 卡 1：先分類，再算分母

「我正在學 C13，請先問我 A–F 各是什麼狀態，等我答完才追問。依序問：E 有沒有足夠答案能評分？F 有沒有啟動？我說的成功率分母是誰？最後要求我用一句客服主管聽得懂的話報告缺證。每次只追一個問題，不先公布解答。」

## 卡 2：像工程師一樣查 D

「這是我的 Q04 設計。先請我把 D 的資料流畫成收到候選→選版→草稿，不先改我的圖。依序追：哪個事件證明收到 D14？若沒收到，調查方向如何改？我怎麼避免串錯 trial？哪些資料不該進 log？我只說『加 tracing』時，要求我補具體欄位和查詢目的。」

## 卡 3：對評分器提出質疑

「先讓我設計一個會欺騙『只看有沒有引用』grader 的答案，再問人工應判哪項失敗。要求我補一個正確短答，檢查是不是過度拒絕。最後請我說如何用保留樣本校準，不能用同一批調規則又宣稱已泛化。」

## 卡 4：面試及規格審閱

「用 Q05 面試我，先聽兩分鐘，依序追總時間→串行假設→品質底線→配額與金額證據。再審我的 Q06 規格：只指出缺少的輸入、trial、停止與驗收，不建立程式、不讀登入檔、不自動改用 API key。未跑處保留待執行。」

若 Codex 算錯或稱某模型已通過，要求它對回合成資料與實際證據。模型可選不等於 lab 已驗收；本卡不自動更改模型。
