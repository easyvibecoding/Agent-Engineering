# C13 · 參考解答

[回題目](README.md)

請先自答再閱讀。以下是可辯護的參考方案；只要假設、權限、取捨與驗證一致，也可接受其他設計。

<a id="c13-q01"></a>

## C13-Q01

task 指定問題、文件與成功條件；兩次 trial 各保留軌跡；grader 檢查引用支持與越權；outcome 為可讀回答案、引用與實際狀態。重跑可能得不同結果，需分開記錄。

**自評：**交付四個概念與具體例子。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c13-q02"></a>

## C13-Q02

schema、目標狀態與工具限制用規則；回答清晰或取捨完整度可用 rubric 與模型，再用人工標記樣本校準。保留爭議題，避免把模型評分當不可挑戰的事實。

**自評：**交付分層評分與校準方式。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c13-q03"></a>

## C13-Q03

取消和失敗不算完成，引用要對應適用來源，trace 檢查是否越權。保留這三種回歸題，使用可觀察輸入與結果；避免只改 prompt 而不修 grader。

**自評：**交付新成功條件與三題回歸。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c13-q04"></a>

## C13-Q04

列 planned、attempted、completed、passed、failed、unknown，說明成功率的分母；同時記錄樣本數、延遲與 token。不可用不同資料分布直接比較，未知費用保持未知。

**自評：**交付比較欄位與控制條件。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c13-q05"></a>

## C13-Q05

定義產品成功與限制，以固定任務、多次 trial、結果與 trace grader 比較；報品質、延遲與實測資源，並抽查錯判和回歸。只憑一次 demo 或 benchmark 排名不足。

**自評：**交付驗證設計與限制。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c13-q06"></a>

## C13-Q06

涵蓋正常、衝突、工具失敗、越權、取消與恢復；固定輸入並重複 trial。額度不足保存錯誤與部分軌跡，暫停新請求；未完成不冒充通過，也不自動改計費。

**自評：**交付題庫、分層 grader 與額度分支。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
