# C12 · 參考解答

先挑你已答過的一題。對照第一個推論就好，發現缺口時先回去改；不必一次讀完。以下是教學推理，不是執行結果。每題四項各 1 分，供自評；不同合理方案若說清前提、權限與證據也可成立。

<a id="c12-q01"></a>

## C12-Q01

遠端可能未受理，也可能已完成 r5 但確認遺失。preparing 與超時都不足以區分兩者。

所以當下可說「關單結果尚待確認，正在查原操作，先不重複送出」。

取得相符操作證據後，才可說「原操作已確認關單完成，結果 r5；已補記恢復結果」。

**判分及替代：**每項 1 分：兩種狀態；傳輸不等於業務；當下保留未知；確認後有證據。可接受加入處理中狀態，不能把 timeout 直接判失敗。

<a id="c12-q02"></a>

## C12-Q02

a1：close-T1042-01／a1／T-1042／r4／原內容；必要時的 a2：相同 operation_id、target、r4 與內容，但 attempt_id 改 a2。

這只是欄位安排。要成立，服務端需比對同 ID 內容、避免併發重複效果、保存並可重播結果。

因此去重過期後原 ID 未必有效，應查證效果或交人工，不創造新 ID 盲目繞過。

**判分及替代：**每項 1 分：兩 ID 分工；目標版本內容不偷改；服務端前提；過期限制。可接受服務端有更長效業務唯一約束，但要說明與驗收，不能自行假設。

## C12-Q03

改新 operation_id 可能繞過去重；把版本改最新則改了原核准的前提。

接著恢復載入原意圖與核准，查 close-T1042-01，再核對 T-1042 的結果及後續歷史；原結果與 r5 關閉相符時，保存完成、來源、結果版本，不再關單。

換成加深變體，只有 closed r5 時可報「目前已關閉，原操作歸因未確認」，保存未知並查歷史或交人工，不重關。

**判分及替代：**每項 1 分：辨識兩種偷換；先查原操作；相符證據後補記；現況與歸因分開。若工單已到 r6，接受用操作歷史證明 r5 曾完成，而非要求現況仍 r5。

<a id="c12-q04"></a>

## C12-Q04

成功且相符→補記；權威確認拒絕無效果→分類原因，只有仍授權、版本與去重契約有效才重試；處理中→有限查詢；僅 closed→保存現況但不假定歸因；查詢失敗→保留未知。

接著檢查循環會不會停。示例最多查 3 次（含首次），a1 之外最多重送 1 次，只能用同一 close-T1042-01 與新 attempt_id a2；整次恢復時限 30 秒。每次動作前檢查並持久扣減對應預算，重送前保留後續查證額度，必要預算耗盡即停止交人工，重啟不歸零。這是可調整設計。

最後檢查核准前提。若未執行而版本已更新，停在衝突並重新判斷及取得必要核准，不自改 expected_version。

**判分及替代：**每項 1 分：五態不混淆；查詢及重送分別有界並有人工下一站；重試前提；版本衝突處理。替代預算可接受，但需連到服務等待容忍度；禁止以找不到紀錄直接證明無效果。

## C12-Q05

先持久保存 close-T1042-01 對應的原意圖與核准；每次傳送另有 attempt_id，工具端以明確契約去重。a1 超時先查原操作，相符才補完成。

各機制仍分工：版本保護舊資料，去重防同意圖重複；取消只停後續或請求遠端停止，已完成需另核准補償。

再看跨系統：資料庫 transaction 不涵蓋外部寄信，不能單憑本地成功宣稱跨系統恰一次。

驗收在回覆遺失處中斷，觀察原操作能恢復且關單與附帶效果沒有新增第二次。

**判分及替代：**每項 1 分：案例清楚；操作 ID 及工具端前提；四機制分責；跨系統限制及實際觀察。可接受其他去重方案，但必須指出保證範圍與失效條件。

## C12-Q06

送出前：無遠端效果，核對後可送一次；執行後回覆前：遠端 r5，本地舊紀錄，查原 ID 補存；回覆後落盤前：重啟仍需同樣查證；版本衝突：無原效果，停止並重新判斷，不能自改版本；查詢一直失敗：效果未知，達限交人工，禁止新增寫入。

五案一起看時，每案保存假核准、原 ID、嘗試、遠端效果與恢復軌跡。成功標準是效果最多一次且證據能收斂，未知案則如實保留未知；不是所有案例都必須完成關單。

如果你的規格只檢查最後 closed，回頭補上效果計數與停止證據。

**判分及替代：**每項 1 分：五案覆蓋；恢復可見資料與測試全知分開；效果與傳送次數分開；未跑狀態及精確驗收。可接受額外併發與去重過期案；不得把規格表勾成已通過。
