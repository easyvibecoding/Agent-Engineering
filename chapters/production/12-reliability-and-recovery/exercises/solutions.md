# C12 · 參考解答

[回題目](README.md)

請先自答再閱讀。以下是可辯護的參考方案；只要假設、權限、取捨與驗證一致，也可接受其他設計。

<a id="c12-q01"></a>

## C12-Q01

operation ID 綁定同一關閉意圖，attempt ID 追蹤各次請求；工具端依契約對重複操作回傳一致結果或拒絕重複套用。保存期限與目標範圍也要明確。

**自評：**交付三項定義與重試關係。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c12-q02"></a>

## C12-Q02

讀取暫時失敗可有限退避；無效參數依明確錯誤修正；權限拒絕停止或正當授權；寫入未知先查 operation 與目標狀態。所有策略都有上限與可見結果。

**自評：**交付四類策略及停止條件。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c12-q03"></a>

## C12-Q03

依原 operation ID 查退款與帳務狀態，確認後補記 checkpoint；不可對應時先停相依工作並人工對帳。只有確認未套用且冪等契約允許才重送。

**自評：**交付恢復觀測與歧義處理。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c12-q04"></a>

## C12-Q04

狀態至少區分取消請求、新工作停止、在途待確認、已完成副作用、補償待授權／執行／待確認。每項有操作 ID 與外部讀回；不能把補償開始視為已還原。

**自評：**交付狀態與證據。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c12-q05"></a>

## C12-Q05

以小增量保存意圖、結果、待辦與證據，使用穩定 ID、冪等工具與有界重試；恢復先核對外部狀態。跨系統不能僅靠本機 checkpoint 承諾 exactly-once。

**自評：**交付機制、限制與中斷測試。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c12-q06"></a>

## C12-Q06

在提交前、提交後回覆前、checkpoint 前與取消時中斷；驗收沒有重複副作用、未知保留可見、恢復後能對帳。所有資料與存放處在本章，沒有生產寫入。

**自評：**交付四個故障點與讀回。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
