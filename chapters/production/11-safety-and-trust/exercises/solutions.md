# C11 · 參考解答

[回題目](README.md)

請先自答再閱讀。以下是可辯護的參考方案；只要假設、權限、取捨與驗證一致，也可接受其他設計。

<a id="c11-q01"></a>

## C11-Q01

政策定義允許範圍，使用者在其權限內授權任務，外部文件只提供資料。模型可從資料提出候選行動，執行器仍依前兩者檢查，不能提升外部指令的權威。

**自評：**交付三個來源與權限邊界。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c11-q02"></a>

## C11-Q02

可預先允許讀取指定文件與受限搜尋；不需要寫入、任意 shell 或憑證檔。若工具需外網，限定目的與傳送資料。新副作用先提出具體操作供審查。

**自評：**交付最小權限與升級條件。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c11-q03"></a>

## C11-Q03

驗收工具拒絕、敏感檔未讀出、未發出未授權傳輸，並保留事件證據。模型最終回答可評估，但不能代替副作用觀測；教學案例使用虛構敏感資料。

**自評：**交付副作用層證據與合成測試資料。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c11-q04"></a>

## C11-Q04

卡片列目標 ID、預期版本、修改前後內容、資料影響與操作 ID。執行時驗證一致性，目標或內容改變就重新審查。UI 好看不等於授權綁定正確。

**自評：**交付核准內容與執行前檢查。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c11-q05"></a>

## C11-Q05

Agent 能讀資料、寫狀態與跨工具行動，錯誤會外溢成副作用。除了輸入輸出行為，還需最小權限、獨立核准、資料與網路控制、記憶來源及稽核。

**自評：**交付風險鏈、控制與驗證。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c11-q06"></a>

## C11-Q06

案例涵蓋外部文件指令、工具描述改寫目的地、記憶提升與核准目標替換。驗收檔案／網路／狀態沒有越權變化，記錄拒絕事件；不使用真憑證。

**自評：**交付四種攻擊與觀測標準。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
