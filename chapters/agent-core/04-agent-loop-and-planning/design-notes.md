# 04 · 設計取捨與疑難

你已經叫助理停下重查。接著要選的是：以後每張單都照固定步驟，還是讓它自己找路？以下用同一張 T-1042 r3 推演，都是設計選擇，不是產品固定要求。

## 取捨 1：固定流程還是讓模型選下一步？

你可能會想：「既然叫 Agent，就讓它決定每一步。」但如果來源永遠只有工單與店規，這個選擇會讓簡單工作多出工具選錯、重複查詢與難以預估次數的代價。

先用固定流程讀兩個來源，再依欄位分支，通常更好查錯。缺資料不是採用動態 Agent 的充分理由，固定流程同樣能交詢問草稿。

何時會吃虧？客戶問題多樣，合法來源也經常變動，你可能為了列完每種情況寫出很多分支。這時才考慮讓模型在限定工具中選路；權限、預算和停止仍留給控制器。

怎麼知道值得換？拿缺欄位、舊政策與無權附件三案比較：交付是否正確、無效讀取是否增加、越權候選是否被擋。不是比較哪個方案的模式名稱更多。

## 取捨 2：再修一輪還是交出目前版本？

你可能怕過早放棄，讓評估器一直叫作者重寫。這在缺陷明確時有用：草稿漏了未拆封，就指定補上條件，改完重查即可。

吃虧的時刻是回饋只剩「不夠好」。它沒有告訴作者修什麼，重寫甚至可能刪掉原本正確的保留語。先把要求縮成一個差異：「移除已符合的承諾，寫出拆封待確認」。

現有 D14 足以修承諾，不足以查明客戶是否拆封。這是兩種工作，不能用更多文字迭代補客戶事實。換模型也不能創造客戶未提供的資料。

驗收先看修正後的文字，再看修正次數。通過就停；用完額度仍不對，就把草稿和缺陷交人工審閱，標成未通過。教材可先假定兩次，真正上限需按任務調整。

## 取捨 3：及早停滯判斷還是容許重試？

你也可能反過來訂「同版回兩次就停」。這很容易檢查，卻會錯殺同版中新讀到的必要欄位。

把判準改成「相同查詢、相同來源範圍、相同缺漏，沒有新增可用資訊」。成功讀取但欄位不存在，改查新來源或提問。暫時錯誤則可有限重試；若已知稍後同步，記下預期更新時點與截止時間再等。

驗證三條路就能看到規則差別：重複同缺漏會停；同版新欄位能繼續；暫時錯誤到達上限會帶原因退出。別只測一路正常完成。

## 常見弱答怎麼修

若你只寫「最多十輪」，追問自己：前九輪都沒價值時，為何還要等？若你寫「completed 所以好了」，追問完成的是哪一層。若你說「取消就還原」，先找已派工作的實際結果，未知也要保留。

[Q03](exercises/README.md#c04-q03)讓你分開無效重查與有價值的修正；[Q04](exercises/README.md#c04-q04)再把它變成轉移條件。現在只選一題，寫出一個能被觀測推翻的規則。
