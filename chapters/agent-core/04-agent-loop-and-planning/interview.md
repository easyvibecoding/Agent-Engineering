# C04 · 面試與追問

## 主問題

「你如何防止 Agent 無限循環？」用 T-1042 r3 在兩分鐘內回答，先自答，再看下方骨架。以下是練習設計，不是真實面試成果。

## 短答骨架

1. **具體失敗：**工單多次回 r3、拆封未知，模型仍要求重讀；問題不在它想得不夠久。
2. **選擇依據：**比較來源、查詢與新增事實。能補缺漏才派工；缺客戶資訊就改交詢問草稿。
3. **控制責任：**模型提議，控制器管權限、次數、修正及時間上限，模型不能自改。
4. **停止與證據：**本輪草稿完成、業務等待資料；記錄原因。用持續相同回傳且模型堅持再讀的故障案驗收。

這是組織答案的方式，勿背成固定句。若你的設計採固定流程，也應說清缺資料與停止分支。

## 由淺到深追問

| 追問 | 面試者需補什麼 |
| --- | --- |
| 最大十輪為何還不夠？ | 無效工作能提前停；十輪內仍可能越權，需另有權限閘門 |
| 同版本就一律停嗎？ | 可能讀到新欄位或另一條款；比較是否補上目標缺漏 |
| 評估器說再寫一次呢？ | 先要求具體缺陷，能驗證才有限修正 |
| 模型要求第十一輪呢？ | 上限由控制器執行，交付未完成部分，不讓模型擴額 |
| 取消是否代表外部操作還原？ | 停止新派工與已派結果分開；結果未知要保留 |
| 固定讀兩份文件需要 ReAct 嗎？ | 不一定，選最簡可驗收流程，避免為模式而增加往返 |

## 常見弱答如何改善

「加 timeout、限制 token」只有保險，補上具體進展判準。「讓 Agent 自我反省」缺驗收，改成「檢查草稿有無 D14 兩條件」。「工具成功就完成」缺層次，改說工具讀取成功、本輪草稿交付、業務等待客戶。

## 自評：四項各 0–2 分

具體輸入與失敗；決策與控制責任；停止後的交付與未知；可重現的故障驗收。0 為缺少，1 為名詞，2 為能用本例說明。分數只找練習缺口。Lab 尚未實作，不能把設計方案講成已部署經驗。
