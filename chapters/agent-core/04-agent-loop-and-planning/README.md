# 04 · Agent Loop、規劃與停止

章節 ID：C04 · 內容修訂：2026-10-21 · 核心約 2–3 小時 · Lab 僅規格。

## 這章解決什麼

讀完資料後，怎麼選下一步，又怎麼避免不停重查？你會把工具結果接成有分支的循環，分開「草稿完成」與「退貨資格仍待確認」。

跳章資料：T-1042 r3 相隔 12 天；D14 要求 ≤14 天且未拆封；拆封未知。只能讀與寫草稿。完整設定見[共同案例](../../../maps/course-story.md)。不需前章的程式或環境。

具體前置：能看懂工具回傳的 ID、版本和未知欄位；知道讀取與寫入的差別。若做不到，先看[第 03 章](../03-tool-contracts/README.md)的工具結果說明，不必先完成整章。

## 核心讀法：2–3 小時

1. 讀[正文](lesson.md)至「把結果交給下一輪」，畫出自己的狀態機，約 45 分鐘。
2. 讀[設計取捨](design-notes.md)前兩項，回答為何不只設最大輪數，約 20 分鐘。
3. 自答[Q01、Q03、Q05](exercises/README.md)，約 40 分鐘。7 天路線只必做 Q01、Q05。
4. 用[Codex 卡](codex.md)逐步追問，或做[面試口答](interview.md)，約 20 分鐘。
5. 按需開[提示](exercises/hints.md)，修正後才看[解答](exercises/solutions.md)，約 15 分鐘。

本章要留下：一張含觀測與下一步的事件表、一份詢問草稿，以及三項狀態：本輪交付、業務進度、停止原因。個人答案放 .study/。

## 深挖讀法：另排時間

正文的四種機制比較、同版本仍有進展的例外、取捨 3，以及 Q02、Q04，各自可獨立練。讀原始 ReAct 研究是理解模式，不要求輸出隱藏思考鏈。[Q06 與 Lab](lab/README.md)只寫驗收規格，不建立程式。

能指出「再讀十次」為何無效、但「修正漏條件的草稿」為何有價值，才算抓到重點。若只記住 routing、ReAct 等詞，回到正文事件表逐列解釋。
