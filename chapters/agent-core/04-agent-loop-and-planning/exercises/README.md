## C04-Q01 · 概念重建

用 T-1042 r3 從接收任務到交付草稿列出 5–7 個事件。每列寫已知／未知、候選動作與選它的理由。最後分開本輪交付、業務進度與外部效果。

**交付與判分：**至少含讀工單、讀 D14、辨識缺漏、草稿檢查與停止；不能把草稿當已寄送。

## C04-Q02 · 方案比較

把「辨識退貨問題」「依序查兩個已知來源」「看到 D07 後改找有效版」「補草稿漏掉的拆封條件」分別對到 routing、plan-and-execute、ReAct、evaluator-optimizer。另回答：若兩個固定讀取即可完成，是否仍需四種機制全部上場？

## C04-Q03 · 軌跡診斷

合成軌跡：連讀三次 T-1042，都是 r3、拆封未知；沒有其他合法資料來源。模型提議再讀十次。另有草稿「12 天內，已符合退貨」。請標出兩種不同缺陷，指定下一步、停止原因，以及各自的驗收證據。

**交付與判分：**不要把重查與修草稿混成同一種重試；解釋為何版本相同不一定永遠等於停滯。

## C04-Q04 · 架構設計

設計執行中、等待資料、等待核准、取消、本輪完成的轉移表。基礎任務只讀及草稿；另設一個獨立變體：使用者要求具體寫入，但尚缺所需核准。給每條轉移事件與守門條件。再假設取消到達時已有工作送出，說明記錄什麼。

**交付與判分：**不把寫入變體套回主案例；取消不推論在途效果已還原。

## C04-Q06 · 未來 Lab 規格

只設計五條 loop 練習：資料完整、缺資料、停滯、核准拒絕、使用者取消。每條寫輸入變體、事件、預期狀態、停止原因與不得發生的動作。資料完整案明示改成未拆封；核准拒絕案是獨立寫入變體。
