# C04 · 參考解答

以下是合成案例的設計推導，不是執行證據。各題 4 項，每項 0–1 分；能提出不同但符合前提、權限與驗收的方案也可得分。分數只用來找缺口。

<a id="c04-q01"></a>

## C04-Q01

1. 接收任務：只准讀取與草稿，限制先進狀態。
2. 讀 T-1042 得 r3：12 天、拆封未知，記錄來源與版本。
3. 讀 D14：兩條件必須同時成立，日期符合、拆封待確認。
4. 確認目前可讀來源無法補漏；下一步改為詢問草稿。
5. 檢查草稿是否寫出兩條件、未知與問題；漏條件才修正。
6. 交付後停止：本輪草稿完成；業務等待資料；沒有外部寫入。

兩個獨立讀取可並行，不要求同一順序。真正要求是結果能影響決策。

**分點判分，每項 1 分：**

- 有觀測、版本與未知。
- 有依結果改變的下一步。
- 分開交付、業務及外部效果。
- 停止原因可由資料核對。

## C04-Q02

辨識任務是 routing；分錯類要有無法分類／人工出口。依序讀已知來源是 plan-and-execute；遇未知仍不能死守「最後核准」。看到 D07 後換查有效版是依觀測調整，可用 ReAct 模式描述；風險是無目的探索。修漏掉的條件是 evaluator-optimizer；評估須指出缺陷，不能只說再好一點。

兩個固定讀取的任務可直接用固定流程，加缺資料分支與草稿檢查，不必另請四個 Agent。步驟可重排或組合，但需說清每次增加往返解決了哪個問題。

**分點判分，每項 1 分：**

- 四種責任對照合理。
- 每種指出具體失敗。
- 承認不是強制四段。
- 最簡方案保留缺漏與停止。

## C04-Q03

重讀是無進展的派工：同查詢、相同來源及缺漏，且無新來源，不派十次。草稿是可修的過度承諾：用現有 D14 補上「拆封待確認」，改成交詢問草稿。

修完逐項檢查後，本輪交付完成；業務等待客戶資料；停止原因 need_customer_information。證據是重複觀測表、修正後草稿與未發出寫入的紀錄。停滯不是模型覺得無聊，而是動作未減少指定缺漏。

同版若讀到此前未讀的必要欄位，仍可能有進展，所以版本只是一項證據。

**分點判分，每項 1 分：**

- 分開無效查詢與可修缺陷。
- 拒絕無理由的十次重讀。
- 修正承諾且保留未知。
- 指出進展不能只看版本。

## C04-Q04

執行中遇到只有客戶能補的欄位，交草稿後本輪完成，另記業務等待資料。若設計常駐工作流程，也可進等待資料，收到新資料且重新驗證版本後回執行中。

獨立寫入變體在權限不足時進等待核准；核准須綁目標與動作，通過才重新檢查並執行；拒絕就結束該寫入要求，不能自批。基礎任務無須建立這個流程。

取消會禁止新派工，保存已派工作的追蹤資料與結果。若結果未知，標未知供後續確認；不能記成已回滾。只有交付通過才標本輪完成，且不自動改業務狀態。

**分點判分，每項 1 分：**

- 轉移有事件與條件。
- 資料與核准分清。
- 主案例與變體分清。
- 取消保留在途結果未知。

## C04-Q05

我會讓控制器記錄每次工具的來源、版本和新增資訊，派工前問這個動作能補哪個缺口。T-1042 連讀仍是 r3、拆封未知，且沒有其他來源，就停止重讀並交詢問草稿；草稿完成，但資格仍待資料。

另設工具次數、修正次數與執行期限的硬上限；相同觀測可提前停，不等用完十輪。模型要求第十一輪不能自己擴額。用工具始終回相同結果、模型持續提議重讀的故障案驗收：應無新派工，且有停止原因與目前交付。

具體數字需按任務量測調整，不把教材的假設上限冒充生產經驗。

**分點判分，每項 1 分：**

- 以具體重複資料說明進展。
- 控制器有不可自改上限。
- 給缺資料的下一步及雙層狀態。
- 測試能對抗持續派工建議。

## C04-Q06

五案可採下方 Lab 的契約。資料完整案：明示未拆封，交符合條件的草稿，仍不退款。缺資料案：r3 未知，交詢問草稿，業務等待。停滯案：重複結果，拒絕多派十次並保存原因。核准拒絕案：獨立寫入請求遭拒，不寫入並結束該請求。取消案：停止新派工，已派讀取結果另記已知或未知。

事件至少記 task、sequence、observation、source_version、candidate_action、dispatch_decision、remaining_budget、stop_reason 及兩層狀態。這些是教學欄位。未來必須用實際事件驗收；本次表格沒有任何已通過聲明。

**分點判分，每項 1 分：**

- 五案輸入與狀態齊全。
- 變體沒有擴大基礎授權。
- 每案有禁止事項與證據。
- 僅規格且不偽造執行。
