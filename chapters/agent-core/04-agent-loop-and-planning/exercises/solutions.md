# C04 · 參考解答

先對照自己第一個不同的判斷，不必一次讀完六題。以下是合成案例推導，不是執行成果；四個自查點各 0–1 分，符合前提與驗收的替代方案也可成立。

<a id="c04-q01"></a>

## C04-Q01

1. 接收任務：只准讀取與草稿，限制先進狀態。
2. 讀 T-1042 得 r3：12 天、拆封未知，記錄來源與版本。
3. 讀 D14：兩條件必須同時成立，日期符合、拆封待確認。
4. 確認目前可讀來源無法補漏；下一步改為詢問草稿。
5. 檢查草稿是否寫出兩條件、未知與問題；漏條件才修正。
6. 交付後停止：本輪草稿完成；業務等待資料；沒有外部寫入。

兩個獨立讀取可並行，不要求同一順序。真正要求是結果能影響決策。

**分點判分，每項 1 分：**

- 有觀測、版本與未知。
- 有依結果改變的下一步。
- 分開交付、業務及外部效果。
- 停止原因可由資料核對。

## C04-Q02

先看決策發生在哪裡，再配模式：

- 辨識任務後分流，是 routing。分不清就留下無法分類出口。
- 已知要讀哪兩個來源，先排步驟，是 plan-and-execute；遇未知仍要改路。
- 看到 D07 才改找有效版，是依觀測調整，可用 ReAct 模式描述；不能無目的探索。
- 已有草稿，按漏條件修正，是 evaluator-optimizer；回饋要指出缺陷。

兩個固定讀取的任務可直接用固定流程，加缺資料分支與草稿檢查，不必另請四個 Agent。步驟可重排或組合，但需說清每次增加往返解決了哪個問題。

**分點判分，每項 1 分：**

- 四種責任對照合理。
- 至少一種指出具體失敗；加深時補齊其他模式。
- 承認不是強制四段。
- 最簡方案保留缺漏與停止。

## C04-Q03

先把兩個下一步分開。

**查詢這邊：**同查詢、相同來源與缺漏，沒有新來源，十次重讀沒有可指出的新增價值，所以不派。

**草稿這邊：**D14 已經寫了未拆封條件，現有資料足夠修正過度承諾。補「拆封待確認」，改成交詢問草稿，再驗一次。

修完逐項檢查後，本輪交付完成；業務等待客戶資料；停止原因 need_customer_information。證據是重複觀測表、修正後草稿與未發出寫入的紀錄。停滯不是模型覺得無聊，而是動作未減少指定缺漏。

同版若讀到此前未讀的必要欄位，仍可能有進展，所以版本只是一項證據。

**分點判分，每項 1 分：**

- 分開無效查詢與可修缺陷。
- 拒絕無理由的十次重讀。
- 修正承諾且保留未知。
- 指出進展不能只看版本。

## C04-Q04

先畫主案例：執行中 → 缺客戶資料 → 草稿驗收。通過才標本輪完成，業務另記等待資料；失敗可修則有限回修，用完額度帶缺陷交回。

若設計常駐流程，也可把業務放等待資料，收到新資訊並核對版本後回執行中。兩種表示法都可以，但要說清「本輪」與「業務」的層次。

獨立寫入變體在權限不足時進等待核准；核准須綁目標與動作，通過才重新檢查並執行；拒絕就結束該寫入要求，不能自批。基礎任務無須建立這個流程。

取消會禁止新派工，保存已派工作的追蹤資料與結果。若結果未知，標未知供後續確認；不能記成已回滾。只有交付通過才標本輪完成，且不自動改業務狀態。

**分點判分，每項 1 分：**

- 轉移有事件與條件。
- 資料與核准分清。
- 主案例與變體分清。
- 取消保留在途結果未知。

## C04-Q05

先用失敗開頭：「T-1042 一直回 r3、拆封未知，更多重讀沒有補上條件。」

接著交代責任：「控制器記來源、版本與新增資訊；派工前問能補哪個缺口。沒有新來源就改交詢問草稿，驗收通過才標草稿完成，資格仍待資料。」

另設工具次數、修正次數與執行期限的硬上限；相同觀測可提前停，不等用完十輪。模型要求第十一輪不能自己擴額。用工具始終回相同結果、模型持續提議重讀的故障案驗收：應無新派工，且有停止原因與目前交付。

具體數字需按任務量測調整，不把教材的假設上限冒充生產經驗。

**分點判分，每項 1 分：**

- 以具體重複資料說明進展。
- 控制器有不可自改上限。
- 給缺資料的下一步及雙層狀態。
- 測試能對抗持續派工建議。

## C04-Q06

先做資料完整案：明示未拆封後，兩條件都符合，可交條件判斷草稿。但新增的是事實，不是退款權限；業務狀態不應照抄「待拆封資料」。

再逐案改一項：

- 缺資料：保留 r3 未知，交詢問草稿，業務等待。
- 停滯：重複結果，不多派十次，保存拒派與停止原因。
- 核准拒絕：獨立寫入請求遭拒，零寫入並結束該請求。
- 取消：停止新派工；已派讀取分開記已知或未知。

詳見 [Lab 五案契約](../lab/README.md)。每案都需事件證據，不能只看最後文字。

事件至少記 task、sequence、observation、source_version、candidate_action、dispatch_decision、remaining_budget、stop_reason 及兩層狀態。這些是教學欄位。未來必須用實際事件驗收；本次表格沒有任何已通過聲明。

**分點判分，每項 1 分：**

- 五案輸入與狀態齊全。
- 變體沒有擴大基礎授權。
- 每案有禁止事項與證據。
- 僅規格且不偽造執行。
