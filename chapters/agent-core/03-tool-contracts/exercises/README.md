## C03-Q01 · 概念重建

為 read_ticket(T-1042) 寫輸入與結果契約。已知 r3 的日期為 2026-10-08／10-20，拆封沒填，任務只讀及草稿。

**交付與判分：**交一張表，分清模型填入、可信環境提供、工具回傳三類資訊；另寫 unknown、unopened 與讀取失敗的差異。結果須含 ID、版本、兩日期、來源與拆封值。

## C03-Q02 · 方案比較

比較 execute(action) 與 read_ticket／close_ticket／refund。情境 A 只有三種操作；情境 B 把工單每一欄都拆成獨立工具，已有 80 個工具。

**交付與判分：**各選一個改善方案，說明權限檢查在哪裡、拆分代價，以及何時合併同權限讀取；設計一個能證明未授權關單未被執行的驗收。

## C03-Q03 · 軌跡診斷

搜尋第一頁回 10 個唯一項目，has_more=true、next_cursor=page-2；模型說「全部只有 10 筆」。變體 A：任務是完整統計，第二頁回 4 個不重複項目且 has_more=false。變體 B：第二頁暫時失敗。假定 A 翻頁期間資料不變。

**交付與判分：**指出第一個錯誤推論；分別寫 A、B 可交付的說法與下一步；說明介面已給完整性訊號時，修正應落在哪一層。不可把工具逾時當成空集合。

[提示](hints.md#c03-q03) · [參考解答](solutions.md#c03-q03)

## C03-Q04 · 架構設計

為缺 ticket_id、讀取無權限、讀取暫時失敗、關單回覆逾時各寫一列。最後一列是獨立變體：操作另有明確授權，但沒收到可靠結果，不適用基礎只讀案例。

**交付與判分：**每列包含可知事實、下一步、重試條件和停止條件。自行選合理讀取重試上限並標為設計選擇；不得把四列都寫成重試。

## C03-Q05 · 面試口答

用讀 T-1042 的例子，兩分鐘解釋什麼叫對 Agent 友善的工具介面。面試官追問：「Schema 已經合法，為什麼還要後端檢查？」

**交付與判分：**先定義少猜測與可查證，再各舉輸入、結果、錯誤一例；分開格式、授權與業務結論。說明一項介面設計代價與可觀察驗收。

## C03-Q06 · 未來 Lab 規格

只寫工具練習規格，涵蓋合法讀取、未知欄位、無權限、分頁、暫時失敗、寫入結果未知六類。不得建立程式、呼叫真實工單或登入。

**交付與判分：**每類列合成輸入、預期工具結果、助理可接受動作、禁止動作與所需證據；寫入未知須明示另獲授權，且與基礎只讀情境隔離。
