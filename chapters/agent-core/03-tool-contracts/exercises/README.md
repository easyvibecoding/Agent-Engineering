# C03 · 題目

先選 Q01 或 Q05 開始，不必一次填完六題。每題先交核心，再補加深；所有資料均為合成。版本：2026-10-21，QID 不變。

基礎案例：T-1042 r3；10/08 到 10/20 差 12 天；D14 要求不超過 14 天且未拆封；拆封未知。只准判斷與草稿，不寄送、不關單、不退款。題內明示變體只適用該題。

14 天必做 Q01、Q03、Q05；7 天必做 Q01、Q05。先自答；個人答案放 repo 的 .study/，需要時才開提示與解答。

## C03-Q01 · 概念重建

為 read_ticket(T-1042) 寫輸入與結果契約。已知 r3 的日期為 2026-10-08／10-20，拆封沒填，任務只讀及草稿。

**先交核心：**先分成三欄：模型提出、可信環境提供、工具回傳。把 ID、版本、兩日期、來源、拆封值放到正確位置。

**再加深：**再各用一句區分 unknown、unopened、讀取失敗。

## C03-Q02 · 方案比較

比較 execute(action) 與 read_ticket／close_ticket／refund。情境 A 只有三種操作；情境 B 把工單每一欄都拆成獨立工具，已有 80 個工具。

**先交核心：**先比較 A 的具名工具與 B 的 80 個欄位工具，各選一個改善方向。

**再加深：**補上權限檢查位置、一項拆分代價，以及如何觀察未授權關單被拒且狀態沒變。

## C03-Q03 · 軌跡診斷

搜尋第一頁回 10 個唯一項目，has_more=true、next_cursor=page-2；模型說「全部只有 10 筆」。變體 A：任務是完整統計，第二頁回 4 個彼此不同、且與第一頁不重複的項目，has_more=false。變體 B：第二頁暫時失敗。假定 A 翻頁期間資料不變。

**先交核心：**先指出模型哪一句推論過頭，再分別寫 A 與 B 的可交付說法。

**再加深：**補各自下一步；介面已有完整性訊號時，該先修哪一層？工具逾時不能當空集合。

## C03-Q04 · 架構設計

為缺 ticket_id、讀取無權限、讀取暫時失敗、關單回覆逾時各寫一列。最後一列是獨立變體：操作另有明確授權，但沒收到可靠結果，不適用基礎只讀案例。

**先交核心：**先列四種錯誤，逐列寫「知道什麼 → 下一步」。

**再加深：**再補重試與停止條件。讀取次數上限由你設計並說理由，不把四列都寫成重試。

## C03-Q05 · 面試口答

用讀 T-1042 的例子，兩分鐘解釋什麼叫對 Agent 友善的工具介面。面試官追問：「Schema 已經合法，為什麼還要後端檢查？」

**先交核心：**先用一分鐘定義問題，舉輸入、結果、錯誤各一例。

**再加深：**再用一分鐘回答後端檢查，區分格式、授權、業務結論，補一項代價與驗收。

## C03-Q06 · 未來 Lab 規格

只寫工具練習規格，涵蓋合法讀取、未知欄位、無權限、分頁、暫時失敗、寫入結果未知六類。不得建立程式、呼叫真實工單或登入。

**先交核心：**先替六類各寫一份合成輸入與預期工具結果。

**再加深：**再補助理允許／禁止動作與證據；寫入未知變體另有授權，不能借給其他情境。
