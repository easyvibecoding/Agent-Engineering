# C03 · 參考解答

這是可接受的推理範例，不是唯一措辭。其他方案若前提清楚、符合資料與權限且能驗收，也可成立。以下皆為教學分析，不是實際執行結果。

<a id="c03-q01"></a>

## C03-Q01

輸入要求 ticket_id；工具依呼叫者檢查可讀範圍。結果回 T-1042、r3、兩個日期及明確的 unknown／unopened 值。欄位名稱可不同，但缺資料不能被默認為未拆封。

**核對重點：**包含精確 ID、資料版本、日期、拆封值及權限負責者。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C03-Q02

分開工具較容易只暴露讀取並在伺服器拒絕寫入，也容易針對各操作驗收。代價是介面與往返變多；可合併同權限查詢，但不宜把任意命令塞入 action。

**核對重點：**說明授權好處與一項代價。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C03-Q03

## C03-Q04

缺參數先補；無權限停止或取得正當授權；暫時讀取失敗有限退避；關單未知按操作 ID 查實際狀態。不可恢復或超過上限要明確停止，不靠換參數繞過權限。

**核對重點：**四類不能全寫重試；寫入未知有讀回。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。

## C03-Q05

友善是讓助理知道何時用、要給什麼、結果能證明什麼。read_ticket 要精確 ID，結果帶 r3 與拆封未知，錯誤分查無與無權限；這樣下一步才清楚，也能讓工程師單獨驗證工具。

**核對重點：**定義後舉輸入、結果及錯誤各一例。 若採不同前提，先明確寫出；不能把題目中的未知直接補成已知。
