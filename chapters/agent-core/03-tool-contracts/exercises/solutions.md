# C03 · 參考解答

[回題目](README.md)

請先自答再閱讀。以下是可辯護的參考方案；只要假設、權限、取捨與驗證一致，也可接受其他設計。

<a id="c03-q01"></a>

## C03-Q01

輸入含精確工單 ID、允許的預期狀態與可追蹤操作 ID；結果含實際狀態、是否已套用或待確認及讀回位置。權限由伺服器依呼叫者檢查，不能由模型傳 admin=true 決定。

**自評：**交付輸入、輸出、授權責任。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c03-q02"></a>

## C03-Q02

窄工具能分別授權和評估，適合不同副作用；受控且同權限的小型動作集合可用通用工具，但不能允許任意未驗證命令。以誤選率與往返量驗證。

**自評：**交付適用條件與一項可量測指標。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c03-q03"></a>

## C03-Q03

結果加入 truncated、has_more 或 cursor 等明確訊號，未知總量就不填確定總數。驗收以超過一頁的集合確認 Agent 會續查或聲明範圍。

**自評：**交付介面修正與跨頁案例。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c03-q04"></a>

## C03-Q04

參數錯誤提供可修正欄位；權限不足停止或請求正當授權；暫時失敗可有限退避；結果未知先查操作狀態。保留 request ID、錯誤類型與可恢復性，刪除機密內容。

**自評：**交付四類錯誤、下一步與停止規則。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c03-q05"></a>

## C03-Q05

具體名稱、少重疊功能、明確單位與前置條件、語意清楚的結果、分頁與錯誤修復訊號。例如將模糊 action 拆成搜尋和關閉，保留精確 ID，便於權限與結果讀回。

**自評：**交付設計原則、例子與驗證。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。

<a id="c03-q06"></a>

## C03-Q06

包含合法、缺欄位、無權限、過期前置條件、重複操作、逾時未知。觀測記錄候選參數、驗證結果、實際狀態與 request ID。測試用資料明確標為教學資料，不接真工單。

**自評：**交付六個案例與狀態判準。 逐項標記「完整／部分／待補」，並寫下下一次要補的證據。替代答案須說明適用假設與如何驗證。
