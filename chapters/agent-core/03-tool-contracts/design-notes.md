# 03 · 設計取捨與疑難

T-1042 仍只准讀取與交草稿。現有工具叫 execute，action 可以填『找工單』『關閉』『退款』；結果只有 success=true，看不出實際讀了誰或是否還有下一頁。

## 取捨 1：工具要拆多細？

先分開讀取與會改狀態的操作，因為權限與失敗後果不同。

**什麼情況換做法：**同權限且語意接近的查詢可合併；拆成過多小步驟會增加往返。

## 取捨 2：大結果要直接截掉嗎？

先回必要摘要與明確分頁／截斷資訊，讓讀者知道覆蓋範圍。

**什麼情況換做法：**需要完整清單時再續取，不能把前 10 筆當全部。

## 常見卡點：錯在哪裡，怎麼改

| 容易說出口的話 | 問題在哪裡 | 較可靠的做法 |
| --- | --- | --- |
| success=true，所以工單已關閉。 | 不知道哪個操作成功，也沒有目標狀態。 | 回操作種類、目標 ID、版本與已確認／待確認狀態。 |
| 拆封欄空白，應該就是沒拆。 | 把缺值當成事實。 | 明確回未知，請模型指出需要補問。 |

## 拿本章案例檢查

工具回得越清楚，模型越少需要猜。精確 ID 與版本也讓之後的核准、重試和讀回能指向同一件事。 用[診斷題 Q03](exercises/README.md#c03-q03)檢查是否能指出具體錯誤，再以 Q04 說明自己的方案。答案若只剩「加強安全／優化流程」，補寫對象、條件與可觀察結果。
