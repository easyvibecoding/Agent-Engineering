# C03 · 面試與追問

## 主問題與短答骨架

先請面試官只問：「工具回 success=true，你敢把結果交給客服嗎？為什麼？」答完這個，再進主問題：「用 T-1042 解釋對 Agent 友善的工具介面。」

自己先口答，不看下面骨架。若卡住，只挑一個具體欄位說明，不必一次背五點。

1. **要解決什麼：**少猜測，能看出要求、結果與下一步。
2. **輸入與責任：**精確 ID 由模型提出，可信身分與授權由執行環境提供。
3. **結果與限制：**T-1042 r3、日期與拆封 unknown；讀取成功不等於退貨核准。
4. **失敗與驗收：**無權限停止、暫時讀取有限重試；驗證不只格式，也看目標、版本、未知及狀態未被越權改動。
5. **一個代價：**工具拆分利於限制授權，但過細會增加選擇與往返成本。

## 面試官追問順序

每次只問一題；回答後先指出一個推論缺口，再進下一題，不把整串問題同時丟給學習者。

- 「你的工具回 success=true，使用者能知道成功了什麼？」期待你補操作、目標、版本與結果含義。
- 「如果 opened=false 原本是沒填的預設值？」期待定位在資料轉換，不能只說換更強模型。
- 「已有 has_more=true 還答總共 10 筆，要修哪裡？」期待指出助理忽略完整性訊號，並安排跨頁驗收。
- 「無權限和暫時錯誤都 retry 有什麼問題？」期待分辨授權與可恢復錯誤，避免繞過限制。
- 「同權限的 80 個讀欄位工具如何改善？」期待合併常一起用的欄位，保留必要資料與缺漏標示。

## 常見弱答如何改善

| 弱答 | 補一句讓它成立 |
| --- | --- |
| 「定義 Schema 就安全」 | 「Schema 管形狀；服務仍依真實身分檢查可讀範圍」 |
| 「要給更多 context」 | 「先修回傳語意，unknown 不得被轉成 false，再給必要欄位」 |
| 「工具越小越好」 | 「依授權與副作用拆分，同來源同權限且常一起用的讀取可合併」 |
| 「一定拿完整資料」 | 「完整統計需續頁；只找特定已取得項目可提早停止」 |

先寫下最想修的一句弱答：______。下一次只重答這句，再做兩分鐘完整口答。

自評每項 0–2 分：需求是否清楚；是否用欄位與事件舉例；是否區分責任與限制；是否給具體驗收。0 缺少、1 只有術語、2 能用案例說明。分數只供練習，不是真實面試成果；Lab 尚未實作。
